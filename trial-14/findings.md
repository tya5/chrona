## Findings
1. Paper size is not a preset property; A4 needs an undocumented viewport (`--viewport 1123x794` = A4 at 96 px/in; PDF MediaBox then 842x595 pt). Default sizes overflow it (`a4css/en-US.png.json` W_LAYOUT_CANVAS_EXCEEDS_VIEWPORT, 1123x986). Owner: core (preset/Layout page declaration) + docs.
2. Row pitch is set by text line + `timeline-row-padding` and `timeline-mark-size`, not by `timeline-row-height` as PROCEDURE step 5 says (`a4b/` row height 13 -> still ~19 px pitch; fixed in `a4d/` by leading/padding/mark-size). Owner: procedure + theme-role reference; core if the token is meant to bind.
3. Derived Theme (v0.16) cannot declare `contrastPolicy` (E_THEME_INHERITANCE_SCHEMA, `r3/`), so PROCEDURE step 10 is impossible on an `extends` Theme; checked via a temporary flattened copy `looks-check/`. Owner: core schema (or procedure).
4. W_LEGEND_COLOR_NOT_SEPARABLE compares ink only: black actual line vs black gate diamond (different shape) fires on every vision (`final/*.json`); reports only the minimum pair, so fixing one pair reveals the next (r1 -> a4d -> final); PROCEDURE claims it only checks scale keys (false). Owner: core rule + procedure.
5. With `--forecast`, future gates are painted with forecast/plan paint (grey #C2C2C2) but the legend `gate` key is black and the `forecast` key is a bar: no key describes a grey diamond (`final/en-US.svg` planned:g-design-freeze fill #C2C2C2). Owner: core (legend from painted occurrences).
6. Baseline Δ column exists only with CLI `--forecast`; a preset/View cannot declare it, and without it the Δ is vs current plan and blank for unfinished rows (`r1/` vs `r2/`). Owner: core/View + procedure.
7. No grayscale/monochrome claim: `colorVision: achromatopsia` refused; `print: photocopy-friendly` is read by nothing (grep src). target-b claims `print-friendly` with orange/blue that merge in grey (`r0/untouched-en-US-gray.png`). Owner: core (make the print claim run a lightness check).
8. View members replace Layout `viewDefaults` wholesale: setting relations `none` in layout.yaml had no effect because the copied view.yaml declares `visibility` (`r1/en-US.png`). PROCEDURE step 8 says View is "usually unchanged". Owner: procedure/docs.
9. Literal, unlocalized strings in ja-JP: View `grouping.missing` is a plain string ("Unassigned"), annotation kind `label` (NOTE/RISK); target-b's copied View hard-codes `countdown.title: 完了まで` (Japanese in every locale) (`r0/untouched-ja-JP.png`, `final/ja-JP.png`). Owner: core (wording keys) + preset data.
10. No resource validation command: `chrona validate scheme.yaml` treats it as a Project ("missing required property 'project'"); only a full render validates, at ~45 s each with relations on. Owner: CLI/core.
11. Calendar-exception band cannot be hatched (`pattern` -> E_THEME_ROLE_PROPERTY_UNSUPPORTED, message does not list supported properties); grayscale shading must rely on lightness only. Owner: core.
12. Untouched target-b on a realistic plan already emits W_SCENE_MARK_CONTRAST, W_SCENE_STATE_TEXT_CONTRAST, W_LEGEND_COLOR_NOT_SEPARABLE (`r0/untouched-en-US.svg.json`), so step 3 "baseline" is not clean. Owner: preset data.
13. Unhelpful diagnostics: W_LAYOUT_AXIS_LABEL_THINNED names `axis-label:4:5` not the label text; W_LAYOUT_ROUTE_FALLBACK says "relation route" for an annotation leader; I_LAYOUT_RELATION_POLICY_SUPERSEDED persists with relations mode none. Owner: core diagnostics.
14. Docs gaps for an outsider: annotation (note/risk) authoring and `fieldRoles` are not in the skill/authoring-model (found in examples/ and Spec 05); as-of `as of 13 nov` lower-case month. Owner: docs/skill.
15. Axis pads to a Q3 band with a mostly empty September column (window starts ~2026-09-22 for a 10-01 plan), and one axis label is thinned at A4. Owner: core (window/axis).
