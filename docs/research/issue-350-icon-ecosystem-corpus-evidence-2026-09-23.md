# #350 Icon Ecosystem Corpus Evidence

**Purpose:** evidence for D350R-1 and D350R-2. This is design input, not a
runtime dependency or a bundled corpus.

## Method

The local `npm pack` packages `@iconify-json/material-symbols@1.2.93`,
`@iconify-json/lucide@1.2.136`, and `@iconify-json/tabler@1.2.40` were unpacked
outside the repository. Their `icons.json` `body` fields were counted without
normalization. No fetched bytes enter the product or its tests through this
research step.

| Collection | Icons | bodies with stroke | arcs | groups | shape elements |
| --- | ---: | ---: | ---: | ---: | ---: |
| `material-symbols` | 16,422 | 0 | 0 | 0 | 0 |
| `lucide` | 1,925 | 1,924 | 1,354 | 1,189 | 749 |
| `tabler` | 6,268 | 5,180 | 5,390 | 2,302 | 3 |

The count includes `fill="none"` on stroke icons, so it is not a paint-style
classification by itself. It does establish that the v0.1 attribute-free,
path-only ingress cannot be a practical set ingestion boundary.

## Consequences accepted by the successor design

1. The importer must process an Iconify collection locally and lower its
   admitted XML shape/group/path vocabulary before closure. Rejecting a valid
   collection's ordinary `fill`, `stroke`, `stroke-width`, cap, join, arc, or
   basic shape is not acceptable for this product scope.
2. The closed normalized vector representation needs per-path `fill` or
   `stroke` mode and completed stroke parameters. It does not admit literal
   colours, gradients, masks, images, CSS, URLs, scripts, or raw XML at any
   post-ingress boundary.
3. The implementation must use real corpus fixtures from all three collections:
   Material Symbols for fill-only near-identity import; Lucide for arcs/basic
   shapes/stroke; and Tabler for mixed normal forms. It must publish the exact
   fixture bytes and importer result identities.
4. The actual default subset must be generated by the importer and its exact
   names/count/size reviewed before publication. Product intent is Material
   Symbols Outline Rounded, addressed by `material:` and
   `material-symbols:`; no unverified corpus count is made normative here.

## Font metric finding

`chrona/font-metrics/v0.1` currently has units-per-em, ascent, descent, and
advances but no cap-height. A cap-height placement rule cannot be honestly
implemented from that data. The successor design therefore introduces a
versioned font-metrics input with an exact positive cap-height, rather than
substituting an unreviewed line-box heuristic.
