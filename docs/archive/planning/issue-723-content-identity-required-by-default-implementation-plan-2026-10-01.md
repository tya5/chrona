# Implementation Plan — Content identity required by default (#723)

Design: [design](../../design/issue-723-content-identity-required-by-default-design-2026-10-01.md). This record holds the acceptance and the slice order; behaviour lives in the design.

## Published, inferred, unverified

Published (read on `main`): the #710 issue, design, plan and review; `storage/revision_store.py`, `storage/snapshots.py`, `operational/store_config.py`, `usecases/local_authoring.py`, `app/cli.py`, `usecases/materialize.py`, Spec 42/54, ADR-0030.

Inferred: that no external Store exists (owner statement).
Unverified: Windows behaviour (the new tests are OS-independent; the three-OS run on `main` is the check).

## Literal acceptance (issue #723)

- [ ] The default is required in the reader (`LocalSnapshotReader`, `LocalBaselineRegistry`) and in Store config (omitted `integrity` means `required`); `optional` remains an explicit opt-out in code, config and CLI.
- [ ] `chrona init --example` writes `integrity: required` (superseded by #727: `optional`, example corpus only), and the Store it creates is readable by its own commands.
- [ ] Tests prove that, by default, an identity mismatch and a missing identity are refused, and that `optional` remains an explicit opt-out; every committed fixture or test that relied on `optional` is migrated deliberately.

## Slices

1. **Docs (this record and the design).** No code.
2. **Code.** One PR:
   - flip the two reader defaults; `ConfiguredStoreReader` default `required` with the flag passed explicitly to the readers; `initialize_project` writes `required`;
   - CLI: `--require-content-identity` becomes `--allow-missing-content-identity` (the generated `docs/guides/cli-reference.md` is regenerated by its tool, not edited by hand);
   - amend Spec 42 (policy text) and the Spec 54 sentence that names the old flag;
   - migrate the tests in the design's blast-radius table;
   - add regression tests that decide from reference data, not the host OS: the default refuses a mismatch and a missing identity on each reader, `optional` opts out, omitted `integrity` is `required`, `initialize_project` writes `required`;
   - mutation-check each new default on a scratch copy.
3. **Verification before merge:** focused tests, the `tests/unit` and `tests/integration` slices that touch Stores, `conformance/run_conformance.py`, `tools/check_import_direction.py`, `python -m tools.derived_evidence --check`, `python -m tools.regenerate_public_examples --check`; PR CI runs the rest.

## Out of scope

`schemas/` (the #710 schema half owns it), pinning the committed example Contexts (reverses ADR-0030; a separate issue if wanted), the baseline reader's token pin (unchanged), derived docs.
