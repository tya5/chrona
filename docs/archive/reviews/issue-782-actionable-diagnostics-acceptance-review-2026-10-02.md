## Architecture and release conclusion

One place decides what a diagnostic row says: `usecases/diagnostic_messages.py`, applied by `usecases/failure_report.py` (error rows, the ladder, `collapse_records`) and `usecases/warning_ledger.py` with `usecases/draft_render.py` (warning rows, `collapse_warnings`). The CLI and the MCP tools print or wrap what these return; the MCP adapter keeps only the 50-row cap, host-path scrubbing and the fixed `E_TOOL_FAILURE` text. No Scene, Layout, scheduler or Core file was changed for the rule, and the Scene `diagnostics` list, the SVG and PNG bytes and the schedule output are unchanged ([`tools/check_import_direction.py`](../../../tools/check_import_direction.py) is clean; no new edge). Rows 4 and 6 are `narrowed`, each with the open successor [#829](https://github.com/tya5/chrona/issues/829).

Intended incompatibilities (review finding F2), each in a golden row or a test, none consumed by anything in the repository: a message that was only a code now says something; the **code** of a `ValueError` whose text carried detail is its leading `E_` token (it was the whole text, `command-check-broken-json`); `validate` and `schedule` of an empty or non-mapping Project are `E_SCHEMA`, rejected, exit 1 instead of `E_TOOL_FAILURE`, failed, exit 2 (design D8, as `render` already was); the number of stderr warning lines is the number of causes, not of placements; the tool set is `chrona/agent-tools/v0.2` (design D9, Spec 66 requires the bump). Every judgement call D1 to D9 is recorded on the issue with options, choice, reason and how to reverse it.

Disclosures:

- **The derived inventory is the backlog, not a gate.** `docs/diagnostics/inventory.md` still lists the 655 bare sites; derived-sync regenerates it, and the guarantee in this change is at the record builder, so a new bare producer is safe but is not flagged. A ratchet is the successor's second criterion.
- **The derived sentence is a guess about meaning.** It says "no further detail is recorded for this code" and keeps the code, so an agent knows it holds the code's name and nothing more; every row the skill, the characterization golden and the MCP tests produce is informative without it.
- **No real agent-host session was run**, as for [#142](https://github.com/tya5/chrona/issues/142) ([#814](https://github.com/tya5/chrona/issues/814)); the effect on an agent is argued from the rows, not measured.
- **Out of scope by design:** the scheduler and `W_DEADLINE` (carried through as a family that supplies its own message), `chrona validate` and cycles ([#780](https://github.com/tya5/chrona/issues/780)), terse-plan (`.chrona`) diagnostics, which use their own record, and the automation-result rows.
