## Architecture and release conclusion

One place decides what an automation-result row says (`stamp_automation_result`, reusing `usecases/diagnostic_messages.py`, the #782 guarantee), and one gate keeps the bare-site population from growing (the policy counts and the ratchet). Owners add the value at the raise site as `ValueError("E_X: detail")`, `ClosureError(..., detail=)`, `ContractError(code, detail)` or `ThemeInheritanceError(code, detail)`, which `report_failure` and the closure and materializer ladders already carry; no new import edge (`tools/check_import_direction.py` is clean: `operational` already imported `usecases`), no Scene, Layout or Core file changed, and the SVG, Scene and schedule outputs are unchanged. The CLI characterization golden changed in two of 114 rows, each explained in its PR: `render-review-store-config-missing` (the message now says the config path is not a file) and `render-view-only` (the `E_ACTUAL_REQUIRED` sentence moved to the raise site and starts with the code like every ValueError row that carries detail). The whole suite ran locally on the final stack (4,645 passed, 31 skipped) and in CI on each PR.

Intended incompatibilities: a few messages changed from a code or a generic sentence to the specific one (the golden rows above); an automation-result diagnostic row has a `message` key it did not have (the schema allowed extra keys already); the derived-inventory backlog text for every code is one sentence instead of two. None is consumed by anything in the repository.

Disclosures:

- **The backlog is smaller, not empty.** 494 sites remain (the 656 measured, minus 162); row 1 is `narrowed` with three successors, each holding the per-package counts, and the policy file is the record that cannot silently regrow.
- **Counts measure sites, not hits.** The order of the slices used the paths an author or agent drives as a proxy; how often each code is reached was not measured (the work record says so).
- **A latent defect seen, not fixed:** `build_review_projection` with no `grouping` and a rollup object in an automatic row mode raises `AttributeError` (`view.grouping.rollup`); it is not a diagnostic and was left out of scope.
- **No real agent-host session was run**, as for [#142](https://github.com/tya5/chrona/issues/142) ([#814](https://github.com/tya5/chrona/issues/814)); the effect on an agent is argued from the rows, not measured.
