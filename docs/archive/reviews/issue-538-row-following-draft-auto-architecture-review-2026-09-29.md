# Architecture Review — Row-Following Draft Auto Sizing (#538)

Predecessors: [published design plan](../planning/issue-538-row-following-starter-work-record-2026-09-29.md) and [design](../../design/issue-538-row-following-draft-auto-design-2026-09-29.md).
Successor: [implementation plan](../planning/issue-538-row-following-draft-auto-implementation-plan-2026-09-29.md).

## Review decision

The proposed distinction is consistent with #468's coherent whole-profile allocation while correcting one boundary that #468 did not separate: its finite 900-unit synthetic closure seed currently enters `resolve_content_block_extent` as the minimum for a Draft auto request. The auto result must be content-sized; finite Draft and immutable requests remain minimum-sized. Keep the request mode at the use-case/Layout boundary rather than inferring it from the synthetic Context value. Auto resolution must verify the final logical viewport allocation for the complete normal-flow profile, not just the timeline host: visible geometry or a large slot in the completed canvas does not prove that the requested allocation satisfies normal flow. Section 13 still requires the completed canvas to contain emitted geometry, including a fixed/capped shortage fallback.

## Architecture consistency

- **Specification 33, Layout ownership:** natural row and profile requirements select one least sufficient whole-profile extent. The final manifest positions the table, timeline, and later siblings together. No geometry is repaired in Scene or an adapter.
- **Specification 08, completed Scene:** Scene continues to carry completed viewport and primitive geometry; serializers do not compute or adjust height. SVG is inspected because Scene-only evidence does not prove serialized output.
- **Specification 50, fallback:** fixed/capped hosts retain the requested finite allocation and truthful short-source/visible fallback. Auto sizing does not turn ordinary fit limits into refusal, nor claim a host grew when it did not.
- **#504 fill behavior:** per-row natural requirements remain the sizing input. The selected host is finalized before `fill` distributes surplus. The sizing resolver must not consume fill-expanded placements as a new requirement.
- **#501 starter gate:** acceptance uses a freshly initialized starter and checks actual output, retaining existing checks for visible table columns, labels, marks, and notes.

## Interfaces, data, and compatibility

Carry the Draft auto intent explicitly to Layout. Keep the synthetic Context finite and schema-valid. The content resolver should accept an explicit sizing floor/mode (or an equivalently typed request) so finite minima cannot be confused with auto's positive finite floor. Its result remains a finite extent plus any exact short-source evidence. It must validate the complete final normal-flow LayoutManifest allocation; completed-canvas bounds are separate evidence and cannot satisfy a failed allocation check. No resource schema, View/Layout Profile schema, persisted Context field, or compatibility reader is required.

The deliberate compatibility change is limited to content-sized Draft auto renders that currently retain unused seed space. Explicit finite Draft and immutable Context dimensions remain minima. Default preset resource bytes and resource identities need not change. Regenerate only materialized artifacts affected by rendered output; compare all generated byte changes before acceptance.

## Risks and required checks

The main behavioral risk is allowing fill expansion to feed back into the natural requirement, which would erase compact auto sizing. Other checks are upward rounding, empty-row behavior, profile intrinsic minima, and preserving fixed/capped shortage behavior. The design fixes these as a one-unit positive empty-content floor, natural requirements before fill, and upward integral rounding. Tests must exercise these boundaries and compare both completed Scene and rendered SVG.
