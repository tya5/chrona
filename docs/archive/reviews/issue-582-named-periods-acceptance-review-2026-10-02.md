## Architecture and release conclusion

The fact is a Project member that never schedules, selected by a View, painted by Theme roles, completed by Layout and carried as ordinary Scene primitives; the label reuses the shared label engine, so the obstacle index, the chip and the suppression and overflow records are inherited, not re-implemented. No Scene schema, Theme schema or Layout Profile changed; `project-v0.7` and `view-v0.28` changed in place with the gate's output recorded in each PR (View needed two reviewed `expected-deltas` entries because its body sits under conditional composition). A Project and a View without `periods` render as before, shown by tests.

Disclosures:

- **A translucent period band cannot be gated for the marks over it** (the Scene contrast gate cannot composite through a translucent host), so the evidence band is opaque and Spec 50 says so; compositing is item 7 of [#871](https://github.com/tya5/chrona/issues/871).
- **The first evidence colour (`neutral`) failed the note-box contrast gate** (1.056 against 1.10) and was replaced by `surface` in the Theme YAML; the gate was not changed.
- **Bundled presets declare no period roles** (the presets lane owns them); a View that selects a period needs them in its own Theme and otherwise fails with `E_THEME_ROLE_REQUIRED`.
- **The state-text closure check now exempts `period-label` as it exempts `annotation-note-text`** (a declared one is still checked); this is the one change to a shared gate and is named in [#870](https://github.com/tya5/chrona/pull/870).
- **Intended incompatibilities: none.** HALCYON Scene `provenance` carries the new Project and Theme identities; the SVGs of the other 26 public slides are byte-identical.
- **Not checked:** macOS and Windows renderings of the new slides beyond the byte-identical derived evidence; the legend lane's entry for a period (successor item 3).

Exact review-bearing-main three-OS CI and newest-Python materializer run must pass before closing #582; record that run in the issue closing comment.
