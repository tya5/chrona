## Architecture and release conclusion

One engine behind every front end: the command line and the tool core call the same functions, no render, Store, schema or Automation Result changed, and the tool core reaches `operational` through two named modules only (`store_commands`, `store_reads`), enforced by `tools/check_import_direction.py` with tests. The SDK is still imported by the binding module only, and the registry is one stable document (`chrona mcp --list-tools` needs no SDK). Tool set `chrona/agent-tools/v0.4`. Every row is `met`; no row is narrowed or deferred, so no successor issue is needed for this issue (the write side and the remaining command types stay in [#902](https://github.com/tya5/chrona/issues/902), unchanged by this work).

Findings of the architecture review that changed the design before code ([work record](../planning/issue-812-mcp-store-read-tools.md) section 4): the cycle has two halves, so one facade is not enough (S1); the command line's snapshot-root mode and its integrity opt-out are not exposed (S2); `integrity: optional` is a legitimate configuration, so "cannot be lowered" means "by a tool input" (S3).

Disclosures:

- **No real agent-host session was run.** The tools are exercised through the SDK client, an in-process client and the real server over stdio, not a host application; the host-transcript issue [#814](https://github.com/tya5/chrona/issues/814) is unchanged by this work.
- **A Store configuration that says `integrity: optional` is honored.** It is the owner's explicit setting (the packaged example corpus writes it, ADR-0030) and applies exactly as on the command line; no tool input can set it, and an agent that can edit the configuration with its own file tools is outside the threat model, as in #813.
- **Reader failures keep the command line's codes and generic messages.** The render closure reports `E_STORE_REFERENCE`, `E_CONTENT_IDENTITY` and `E_CONTENT_IDENTITY_REQUIRED` with the curated "no further detail" message of `usecases.diagnostic_messages`; the comparison reports the engine's specific message. Improving the closure's messages changes that shared table and is not part of this issue's acceptance.
- **Store reads have no size cap.** Content identity binds the bytes and an asset such as a font is legitimately large; a YAML document inside a Store that expands without bound is as dangerous through the tool as through the command line.
- **A Store changed while a call reads it** is read as either the old or the new bytes, and the identity check catches a mismatch; the check and the read are separate steps, as for every tool.
- **`--format`, `--reject-unused-closure-inputs`, `--emit-scene` and the snapshot-root mode of `render-review`** are not offered by the tools; none is an acceptance row, each is additive in a later tool-set version.
- **The mutation check was run locally** (the evidence is the pull-request comment), not in CI.
- **Windows and macOS evidence is the exact-main three-OS run named in the closing comment.** The binding and stdio tests skip without the extra and the link tests skip only where the OS cannot create a symlink; the run's job logs decide whether they ran there.
