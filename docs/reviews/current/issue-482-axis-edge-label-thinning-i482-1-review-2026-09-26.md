## Architecture review

`thinning_schedule` (`axis.py`) is now a direct filter (`retained = {i : fits[i]}`), not a periodic-stride search; `AxisThinningSchedule` carries `retained_positions`/`thinned_positions` only. `surface_composer.py`'s `thin-with-record` block always assigns `reason="label-does-not-fit"` to a thinned candidate (the `"thinning-stride"` branch is unreachable and removed), and `W_LAYOUT_AXIS_DENSITY` reports `thinned=<count>` instead of a stride/phase pair that no longer describes anything. `surface_quality.py`'s `AxisTierOutcome.__post_init__` invariant was tightened in the same commit to reject the now-dead `"thinning-stride"` reason, so a manifest cannot claim a disposition the corrected code never produces. No View, Theme, Scene, or adapter file changed; no schema changed. Layer ownership is unchanged from the accepted amendment: `thin-with-record` remains a deterministic Layout policy over completed interval outcomes.
