One correction to the PR. Its first count table said "0 changed rendered output". That was true of the SVG only. The Scene provenance records the content identity of each Theme resource, so editing five preset Themes changes the Scene hash (not the SVG) of every render that uses them. Three pinned Scene hashes moved with it and were updated on purpose in the PR ([`test_label_chip_shapes`](../../../tests/integration/test_label_chip_shapes.py), [`test_annotation_list_status`](../../../tests/integration/test_annotation_list_status.py), [`test_chip_box_follows_text`](../../../tests/integration/test_chip_box_follows_text.py)); their SVG hashes did not move. The PR body now carries that correction.
