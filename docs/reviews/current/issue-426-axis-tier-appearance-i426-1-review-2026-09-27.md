- **Focused tests:** `.venv/bin/python -m pytest -q -n 6 -p no:cacheprovider tests/unit/chrona/presentation tests/integration tests/cli tests/acceptance` — **984 passed**, 21 skipped.
- **Literal regression tests** (`tests/unit/chrona/presentation/scene/test_v05_builder.py`), each written to fail on `06740ce2` and pass after `c55d6c05`:
  - `test_two_band_tiers_each_render_in_their_own_non_overlapping_lane` — criterion 1. On `06740ce2` both declared band tiers render at the whole axis slot (`block=0`, `blockSize=48`), so the assertion that the two lanes are disjoint fails immediately.
  - `test_two_band_tiers_resolve_different_fills_from_the_theme` — criterion 2. On `06740ce2` the second band tier's rect still carries `semantic_id="axisBandDecoration"`, so `second_band.visual_role == "axis-band-decoration2"` fails.
  - `test_two_labels_tiers_resolve_different_sizes_weights_and_colours` — criterion 3. On `06740ce2` every labels tier is hoisted to the single `axis_treatment`/`typography_role="axis"` computed once outside the tier loop, and every label's `semantic_id` is the literal `"axisLabel"`, so `quarter_label.visual_role == "axis-label2"` fails.
  - `test_a_single_band_tier_keeps_spanning_the_whole_axis_slot` — the byte-identity carve-out (design §2.2): explicit regression that a View with exactly one band tier is unaffected.
- **Public materializers:** `tools.regenerate_public_examples --write --jobs 6`, then `--check`, reproduce 23 slides (22 existing + the new `controller-z/axis-tiers` slide). Every changed `generated/*.scene.json` was compared structurally against its prior committed version with only the View provenance resource's `contentIdentity` field stripped; all 21 are then byte-equal, so the sole content difference in each is that one hash, caused by the View v0.24 version-string migration (`0e75e9d6`), not by any geometry or primitive change from the axis tier implementation (`c55d6c05`). - **Rendered inspection:** a PNG crop of `examples/controller-z/generated/axis-tiers.svg`'s axis region shows two visually distinct stacked lanes: a bold white-on-blue quarter tier directly above a smaller dark-on-light month tier, matching the Editorial reference from the issue.
- **Generated reports:** `tools/diagnostic_inventory.py`, `tools/presentation_contrast.py`, `tools/presentation_font_identity.py` and `tools/presentation_coverage.py` were rerun and each moved only to add the new slide's rows / adjust its own witness bookkeeping; `presentation_contrast.py`'s decoration-witness check now also treats `axis-band-decoration2` as witnessed by the new slide.
- **Conformance:** local `conformance/run_conformance.py` — **PASS**, all 31 checks.
- **Hardcoded corpus counts:** `tests/acceptance/output/test_public_geometry_regressions.py` hardcodes the public scene/SVG count and two derived label counts; all four were updated deliberately (see that commit's message for the arithmetic) since the new slide changes them.
- **Problems found and corrected before this review, recorded here rather than silently fixed:**
  1. The first implementation attempt assigned a labels-tier semantic id purely by declaration ordinal, exactly mirroring the band scheme. That broke every existing View immediately: all 18 corpus Views declare two labels tiers with no `typographyRole`, and the ordinal scheme would have required a Theme role (`axisLabel2`) none of them declare. Corrected to: a labels tier that leaves `typographyRole` unset keeps the shared `axisLabel` id regardless of position; only a tier that explicitly names a role claims the next ordinal id. Bands did not have this problem because every corpus View declares exactly one band tier, so the count-based carve-out already covers it.
  2. `v05_builder.py`'s `emit_semantic_text` call for axis text passed a hardcoded `"text"` visual-role override, which meant a labels tier's *paint colour* (not its font, which is already resolved per tier by the explicit `typography_role` parameter) was always the shared `text.fill` colour regardless of semantic id. Removing the override (it now resolves each id's own registered scene role) was necessary for the "different colours" half of criterion 3, and is byte-identical for `axisLabel` (whose scene role is already `"text"`).
  3. `axis_band_host` matched a label's host band by inline (x) position alone; once bands occupy different lanes this could select a band that overlaps a label's *column* but not its *lane*. Added a block/lane containment test alongside the existing inline one, confirmed against the committed evidence: quarter labels host to quarter band rects, month labels to month band rects, never crossed.
  4. Three call sites had literal `"axisBandDecoration"`/`"axisLabel"` string checks beyond the two named in the design (`surface_quality.py`'s host-validity check and `axis_band_host`): `BACKGROUND_SEMANTIC_IDS`, `shape_slot`'s axis-slot dispatch, and `v05_builder.py`'s shape-emission branch. All four (including the two designed ones) now read from the shared closed id functions.
  5. A pre-registered third band ordinal (`axisBandDecoration3`) tripped `tools/presentation_contrast.py`'s corpus-wide decoration witness (every `ContrastClass.DECORATION` role must be painted somewhere in committed evidence). Removed it: two band ordinals are sufficient for the literal criteria and the committed example; a third labels ordinal (`axisLabel3`, not contrast-classified) was kept since the committed example's two labels tiers are both explicitly typed and need two ordinal ids at once, alongside the shared default `axisLabel`.
  6. `tools/check_semantic_registry_reachability.py` performs a syntactic scan for semantic-id string literals; indexing a plain module-level tuple constant (`AXIS_BAND_SEMANTIC_IDS[i]`) is invisible to it. Converted the two id lists to zero-argument functions (`axis_band_semantic_ids()`, `axis_label_semantic_ids()`), matching the existing `label_host_semantic`-style pattern the tool's "factory" mechanism already recognizes.
  7. `tools/check_layout_float_accumulation.py` rejects `sum(1 for ... if cond)` as unclassified float accumulation; rewritten as `sum(cond for ...)`, the idiom the tool already accepts elsewhere in the file.

## Architecture review

Layer ownership unchanged: View states only a Theme role name (`typographyRole`); Layout alone turns that into lane geometry, semantic id selection and host/contrast resolution; Theme states tokens under role keys; Scene carries the already-completed primitives with no new dispatch logic beyond reading the same closed id sets Layout and surface-quality use. No Scene schema, adapter, or ColorScheme contract changed.

The single-band carve-out (design §2.2, accepted by the lead) is the one non-uniform rule: `compose_surface_layout` branches on `band_tier_count == 1` before choosing between the historical full-slot rect and the new per-lane formula. This is documented normatively in Specification 39 §1.2, not left as an implicit accident of code order.
