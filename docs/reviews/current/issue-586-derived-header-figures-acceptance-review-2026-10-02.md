## Architecture and release conclusion

The facts are existing Core values (the Actual Set as-of, a resolved period, a placed endpoint); the arithmetic is one pure Core module reusing `Calendar.is_working`, and its working-day count is the scheduler's `advance` convention, proven by a round-trip test, so a figure and the scheduler cannot disagree on what a working day is. The use case only gathers facts and refuses on findings; content substitutes finished integers; Layout, Scene and adapters see strings. The declaration is a View member (not a Summary Profile source) so header text and the summary share one declaration, and the set of kinds and facts is closed by the schema and by the Core registry with no expression anywhere. Both schema additions are optional and in place (Specification 56 section 3.2): omission is today's output, declared-but-unused figures leave every Scene primitive equal, and every committed slide other than slide 02 (and the provenance of slides 11 and 12) regenerates byte-identical (no-change evidence only, not a quality bar).

Disclosures:

- **Eager resolution** (decision D4): a View that declares an as-of figure cannot render against a Context with no Actual Set; such a View should declare other figures. Reversible in one use-case function.
- **Header placeholder limit:** the value is the same in every group's header; group-relative facts, further kinds (counts by state, finish delta), other label surfaces and a `last` side of a period are the optional extensions in [#927](https://github.com/tya5/chrona/issues/927).
- **Shared guards touched:** the id-site count of `view-v0.28` in `tests/unit/tools/test_schema_identifiers_and_license.py` (17 to 19, the two new `id` sites keep the `minLength: 1` form), the S0 expected-delta file (three entries), `tests/support/synthetic_review.py` (an optional `summary` argument to `render`).
- **Local-only failures, not product defects:** the generated `diagnostic-inventory` and `presentation-coverage` reports and the materializer Scene-evidence comparison differ in a working tree until the derived sync regenerates them; the PR checks compare against the disposable snapshot and passed.
