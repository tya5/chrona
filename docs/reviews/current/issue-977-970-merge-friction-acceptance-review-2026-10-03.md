## Architecture and release conclusion

Both slices are test and tool code; no layer, schema, Scene or public contract changed. #977 reads only manifests and generated files, as the corpus tests already did, and its comparison is a pure function tested on hand-built input. #970 changes what the gate reports and the file's hygiene, never what it accepts. Specification 56 and AGENTS.md step 3 each gained one sentence, and the deltas file header states the lifecycle.

Disclosures:

- **A slide PR adds one ledger line.** The criterion "adding a slide does not edit a test" is met as written (no test changes) but the PR still adds a data row; the failing test prints the line. This is the price of "every slide accounted for and none changes silently", chosen over rows for exceptions only (J1).
- **The stale gate is part of the manual `--base-rev` step.** Nothing in CI runs it, because the base-less conformance run would fail unrelated PRs for another PR's debt (J4).
- **Branches that appended entries at the end of the deltas file** (#585) will see a trivial conflict where merged entries were pruned.
- **Entry revisions are derived from history**, so a checkout without it cannot age an entry; when the base revision's history is missing the run notes that merged entries were not checked and judges every entry as before.

Exact review-bearing-main three-OS CI and the newest-Python materializer run must pass before closing #977 and #970; that run is recorded in each closing comment.
