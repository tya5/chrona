## Architecture and release conclusion

Registry says what a role is; the completed-Scene policy turns a ratio into a finding whose severity follows the class; the render use case reports the warnings and enforces the Theme's choice; the corpus tool aggregates; Layout and adapters are untouched. No floor, ground, code or Theme-resolution check of marks or text changed. `theme-v0.11` and `theme-v0.13` gained the optional `contrastPolicy` in place (Specification 56 section 3.2); the S0 gate `python -m tools.schema_equivalence --base-rev origin/main` passed on the C995-2 PR with both schemas `additive`. No corpus datum, preset or example was edited.

Disclosures:

- **The packaged default preset now warns.** The editorial row-band zebra is 1.013:1 against 1.10, so a default `chrona render` of the starter project prints one collapsed warning (13 CLI characterization cases re-recorded). A true finding the corpus never showed; not changed here (decision recorded on #995).
- **Unreadable decoration hosts warn too.** A decoration over a translucent host cannot be measured; that is a missing measurement, not an illegibility. A mark or text on a translucent host stays a blocking `E_SCENE_CONTRAST_GROUND_UNSUPPORTED`.
- **The corpus tool cannot see the knob.** It reads Scenes only and always evaluates with `warning`; a Theme that declares `error` cannot put a failing decoration in the corpus because the render that makes the Scene fails first.
- **Every render evaluates the Scene** (one pass, the order of the perceptibility check that already runs on draft).
- **`E_THEME_CONTRAST_POLICY`** is reachable only by a caller that bypasses the schema (which reports `E_THEME_SCHEMA` at the exact pointer first).
- **The issue's list is wider than the classified roles.** Grid and separator lines, canvas texture, region frames, chips, dependency lines and free labels carry no contrast class, so the gate has never produced a finding for them: nothing about them blocked before and nothing is added. Only registry-classified decoration roles warn.
- **Free labels on the shared text role** stay ungated ([#980](https://github.com/tya5/chrona/issues/980)), unchanged.

Exact review-bearing-main three-OS CI and the newest-Python materializer run must pass before closing #995; that run is recorded in the closing comment.
