## Architecture and release conclusion

Runtime guard, two consumers and five schema lifecycles; no Scene byte changed in any slice. The security-relevant part, the runtime guard now equal to the schema, is done and tested; the schema work that remained after #710 is done for every site the code opens, and the one family it deliberately leaves, the Project evidence references, is a question about whether they should be opened at all.

Disclosures:

- **A premise failed and the plan changed.** The in-place reading for the three leftover sites was false as stated, and the previous agent stopped instead of forcing it. The consumers were changed first (the preset-library guard and the icon-catalog parse-time check), then the schemas followed in place. The icon-catalog check applies to v0.4 only; the Material catalog is v0.3, so it is unchecked and keeps its own pattern, and a test pins that.
- **Moving a site to `storeAddress` also widens it.** A leading `.`, `_` or `-` is newly accepted by both schemas (the old patterns required a letter or digit). The shared guard already accepts it, so no consumer is harmed; it is recorded in the design, Spec 56 and the S0 deltas.
- **Probes added to the gate.** The slice added 90 probes to `tools/schema_equivalence.py` and merged them into the baseline file as pure insertions recorded at the base, so deltas could be expressed; this was outside the plan.
- **Load time was measured on a laptop.** The worst case for the icon-catalog check (4,015 raster entries) cost 483 ms against 604 ms, about 1.25x, and the shipped Material catalog is not checked; the S3 slice recorded 0.24 to 0.30 s and the test budget is 10 s. It was not measured on CI-comparable hardware.
- **A consequence of the snapshot-ref writer change.** A loose-address Project reference passed directly to the writer is now written as v0.3 as built, which breaks its own schema. The v0.3 command schema blocks it through the CLI and no caller does it; no validation was added because two existing tests publish incomplete references.
- **Squash bodies without trailers.** The squash bodies of #750, #754, #756 and #757 carry no co-author or session trailers; they were added from #762 on. The pushed commits carry them.
- **A diagnostic moved earlier.** A materialize `directory` of `out dir` or `出力` is now refused by the guard as `E_AUTHORING_MATERIALIZE_PATH` instead of by the workspace contract as `E_RESOURCE_SCHEMA`.

Exact review-bearing-main three-OS CI and newest-Python materializer run must pass before closing #731; record that run in the issue closing comment.
