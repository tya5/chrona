# Architecture Review — Rule-based lane acceptance (#467, #494)

**Reviewed:** [rule-based correction](../../design/issue-467-494-rule-based-lane-acceptance-correction-2026-09-27.md), [design plan](../../planning/active/issue-467-494-rule-based-lane-acceptance-design-plan-2026-09-27.md), Specs [38](../../specification/38-review-row-composition.md), [46](../../specification/46-completed-scene-paint.md), [50](../../specification/50-constraint-driven-gantt-surface-quality.md), selected #467 lane design, #466 phase-one text obstacles, View v0.27, S2a facet/provenance contract, #480/#481/#486/#487 geometry/table/group dependencies, and #494 route criteria. **Public base:** `b986ed0b8d79337c7abe9edf2b2dfef65edf562b`. **Decision:** accept for implementation planning; numerical acceptance gates are superseded.

The revised rule tests the quality of the completed layout, not an arbitrary lane total. Reading actual Scene geometry avoids accepting a Layout-only estimate that fails serialization; typed lane/member provenance avoids decoding IDs or guessing by geometry. Scene remains a completed-primitives/identity projection, while the read-only checker owns no placement decision. The pairwise audit uses both move directions and the same visible-stroke/clearance semantics as Layout, with labels and icons included. An unapproved chain-only exemption is impossible because the current rule is a positive predecessor preference, not an enforced lane-separation constraint. The mark-only overlap sweep is a valid lower bound; full-footprint inline concurrency is reported separately to explain 2D label pressure without falsely treating it as a bound. This is consistent with the owner's explicit caveat that the lower bound is explanatory, not a target.

Adjacent obligations remain: selected 4wd chain, all packed names and deltas visible, deterministic insertion, all packaged defaults, at least three reproducible lane slides, and #494's measured route causes/no label crossings/attributed membership. The WIP 13-lane artifact still lacks chain and cause evidence and cannot satisfy release acceptance. Optional Scene provenance requires a versioned schema/serialization change only for lane-mode primitives; old modes must remain byte-identical. The Scene audit and rendered SVG/PNG check must agree on source-visible content. If glyph/icon geometry cannot yield a comparable Scene footprint, pause B2 and return to design. The current S2b port-host correction remains independent and should finish before B2 integration.

**Next:** publish an implementation-plan amendment replacing the L3b numeric pause and removing the unnecessary above-ten runtime rejection trace. Keep focused tests local, batch public materializers/SVG review, and use CI for the full matrix at material release.
