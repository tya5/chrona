# Architecture Review — Scene lane anchor (#467, #494)

**Reviewed:** [anchor correction](../../design/issue-467-494-scene-lane-anchor-correction-2026-09-27.md), [rule-based acceptance](../../design/issue-467-494-rule-based-lane-acceptance-correction-2026-09-27.md), Specs [38](../../specification/38-review-row-composition.md), [46](../../specification/46-completed-scene-paint.md), [50](../../specification/50-constraint-driven-gantt-surface-quality.md), current Scene v0.6 model/schema/serializer, Layout lane preflight, S2b port-host design, #466 required-label obstacles and #494 route criteria. **Public base:** `94d233dc6adfb7e8f361ec2476f9737c906c246f`. **Decision:** accepted; B2 must implement the typed anchor before its Scene audit is credible.

The field resolves a geometry/identity seam without moving placement into Scene. Layout alone owns the final mark-band position; Scene transports it with completed row geometry. A rigid-move checker then reads actual Scene footprints and a typed anchor, not a guessed center or a second Layout solve. The port host remains separate from visible geometry. Adding optional lane-only Scene v0.6 fields preserves the existing automatic/explicit artifact bytes while making repeated source instances and visible-overflow labels auditable. No target adapter is allowed to choose or repair the anchor.

The predecessor design's v0.5 reference was a factual error; current public serialization and schema are v0.6, which this correction names. The schema migration is additive for lane-mode evidence, but model/schema/serializer/tests and generated public lane artifacts must ship together. The pairwise checker test matrix in this correction closes the implementation-plan coverage gap found by independent review. If a Scene primitive's visible footprint cannot be reconstructed consistently with Layout's admitted stroke policy, return to design; do not fall back to Layout-only acceptance.
