## Architecture review

- **Theme:** `schemas/theme-v0.11.schema.yaml`'s `symbol` value gains an additive `glyph` shape (`oneOf` alongside the unchanged 4-shape object); no version bump. `milestoneSymbolActual`/`milestoneSymbolBaseline` are new optional role properties; the schema already allows any role name with a `symbol` property, so no schema change was needed for the role names themselves.
- **Scene:** `SymbolGeometry` (`scene/model.py`) is unchanged. `ScenePrimitive` gains two transient fields not read by `scene/serialization.py` (see the design correction, `f485ef9a`); `schemas/scene-v0.6.schema.yaml` is untouched, matching the reviewed precedent of additive fields landing under one version string.
- **Layout:** unchanged. `layout/ports.py`/`layout/relation_terminals.py` still compute a connector's port from the mark's bounding box only; the committed slide's glyph is authored full-bleed in its `viewBox` (verified directly by `test_glyph_gate_geometry.py`, not merely assumed), satisfying the documented authoring constraint from Contract 6.
- **Contrast/perceptibility:** `contrast_policy.py::_ground_under` now accepts a prior `Symbol` as ground, alongside the existing `Rect` case; every other rule (paint-order/index, bounds containment, opacity/gradient handling) is untouched. `perceptibility.py` needed no change (`_occlusion_findings` only ever compares `Text` against `Rect`).
- **Adapters:** `renderers/v05_svg.py` needed no change, confirming the design's prediction — a glyph gate is several ordinary single-outline `Symbol` primitives, which the adapter already knew how to draw.
