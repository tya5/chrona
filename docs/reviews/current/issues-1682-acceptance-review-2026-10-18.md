## Architecture conclusion

Profile checking now has one entry point (`check_project_extensions`) for `validate`, `schedule`, draft render and the MCP tools, with the published `E_PROFILE_*`, `E_EXTENSION_UNRESOLVED` and `E_CONTENT_IDENTITY` diagnostics. A profile `default` is filled once, in the per-source accessor, so Snapshot, scenario, row and folded occurrences agree and the stored fields are never rewritten. A colour encoding no longer refuses objects whose profile does not declare the field. All four rows are met. Limits stated, not hidden: the issue text swapped `bad.yaml` and `bad2.yaml`; the declared-without-value refusal and the `default: false` colours are verified by tests (and, for the default, by a successful render), not by a trial picture; there is no dedicated MCP test. #1682 can close on rows 1 to 4 once the reviewer agrees; this review does not close it.
