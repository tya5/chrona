# Issue #782 — Actionable and De-duplicated Diagnostics: Architecture Review

**Decision:** Accept the [design](../../design/issue-782-actionable-diagnostics-design-2026-10-02.md)
**with conditions**. The rule and the placement in the use-case layer stand. Three
findings change the plan: an existing multiplicity test must be replaced by a
stricter invariant (F1), one deliberate status and exit change must be disclosed
(F2), and two diagnostic surfaces are outside this change and need a recorded
disposition (F3, F4).

Reviewed: the [design plan](../../planning/active/issue-782-actionable-diagnostics-design-plan-2026-10-02.md),
the design, [Spec 66](../../specification/66-agent-interface.md), [Spec 50](../../specification/50-constraint-driven-gantt-surface-quality.md)
(suppression facts), [Spec 56](../../specification/56-schema-authoring-and-diagnostics.md)
(schema messages), Spec 09 (dependency direction), `tools/check_import_direction.py`,
the #142 [architecture review](issue-142-agent-interface-architecture-review-2026-10-01.md) finding F8,
against `main` at `32a5fb4b`. Checked by running the CLI on mutated copies of the
skill's example and by reading the sources named below. Not checked, and recorded
as such: any agent host's behaviour on the new rows, and the wording quality of the
derived sentence against a real agent.

## Boundary audit

| Boundary | Decision | Result |
| --- | --- | --- |
| Producers (Core, Scheduler, Layout, Scene) -> use case | Identity strings, `Diagnostic`, `FitWarning` and the Scene `diagnostics` list are unchanged; prose is added above them | Preserved. No scheduler file is touched |
| Use case -> adapters | `failure_report`, `warning_ledger`, `draft_render` own message and collapse; `app/cli.py` and `app/agent_tools.py` print or wrap | Preserved; the MCP adapter loses its own dedupe (D7) |
| `diagnostic_messages` -> layers | Reads strings and mappings only; imports nothing from `presentation/` or adapters | Holds; `check_import_direction.py` unchanged |
| Scene JSON and SVG/PNG bytes | Not an input of any change | Preserved; conformance and derived evidence stay byte-identical |
| CLI JSON shape | New keys only (`message` on warnings, `count`, `occurrences`) | Additive, with the changed values of F2 listed |
| Derived inventory | The `StableFailure` sites move rows from "bare" to "detail"; `inventory.md` is regenerated by derived-sync | Preserved; never hand-edited |

## Findings

### F1 (high): an existing test pins the behaviour being replaced

`test_cli_warning_inventory_equals_scene_diagnostics_for_attached_milestones`
asserts `Counter(CLI identities) == Counter(Scene identities)`, the guard that a
transport does not drop a warning, and `warning_ledger` documents "keep warning
multiplicity". A collapse breaks both by design. *Disposition:* replace the guard
by the multiplicity invariant of the design (sum of `count` per code equals the
Scene count per code; every listed identity is a Scene identity), which is
stricter about loss and independent of row count. The test is changed in the same
slice as the collapse and the change is named in the PR. The Scene keeps every
fact, so Spec 50's count equality is untouched.

### F2 (medium): not every change is additive

Additive: `message` on warnings, `count`, `occurrences`. Not additive, all
intended: messages that equalled a code; the `sourceRef` of `LayoutError` and
`ColorSchemeError` rows (`/` to the reported location); the number of stderr
warning lines; and D8, where `validate` and `schedule` of a non-mapping Project
change from `failed` (exit 2, `E_TOOL_FAILURE`) to `rejected` (exit 1,
`E_SCHEMA`). A consumer that keys on `message == code`, on `E_TOOL_FAILURE` for a
malformed plan, or on a line count per warning would notice; none exists in the
repository (searched tests, skill, guides). *Disposition:* each is a row of the
golden diff with a reason, D8 is called out in the PR title line and in Spec 66, and
the acceptance review lists them as "intended incompatibilities".

### F3 (medium): plan (`.chrona`) diagnostics use another shape

`app/cli.py` reports Core findings on a terse plan through `position_findings`
and `_compile_failure` (`item.as_dict()`, line and column), not through
`diagnostic_record`. Their messages derive from `Diagnostic.message`, which the
guarantee does not touch. *Disposition:* out of scope. Whether a Core
`Diagnostic` with an empty message can reach that path was not checked; the S1 test
that builds a row for every inventory code covers the shared builder only, so the
implementation plan adds a Core-side check (every `Diagnostic` raised in `core/`
and `scheduling/` has a non-empty message, by reading, not editing, those files).

### F4 (medium): automation results carry code-only rows

`chrona/automation-result/v0.2` (`command-check`, `command-apply`, `actual-*`,
baselines) and one literal in `app/cli.py` emit `{"code": ...}` rows under a schema
of their own. They are not reachable from the four MCP tools and are not part of
the draft path an agent drives. *Disposition:* deferred with a successor issue
(filed at acceptance, with the 233-code backlog), not widened into this change.

### F5 (low): the derived sentence must not read as an answer

A sentence generated from a code name can sound authoritative. The derived text says
"no further detail is recorded for this code" and keeps the code, so an agent knows
it holds a guess about meaning, not a diagnosis. A test that every code in the
characterization golden and in the skill's table has a curated entry, and that the
derived branch is reached only by codes outside those two sets, keeps the sentence
for the codes an agent actually meets from being a guess. *Disposition:* accepted as designed (D3).

### F6 (low): messages may carry plan data

A warning message names a subject such as an object id from the plan. That is the
point of the rule, and the MCP adapter's path scrubbing already runs over every
message. *Disposition:* no change; the Windows and macOS runs cover the golden's
path normalisation as before.

### F7 (low): determinism

The merged row sits at its first occurrence, `occurrences` keeps encounter order,
and the table lookup is by code. Two runs print the same lines; the MCP envelope
stays sorted as today. *Disposition:* a repeat-run equality test is part of S2.

## Architecture conclusion

| Check | Result |
| --- | --- |
| Responsibility ownership | One owner for prose and collapse (use-case layer); producers keep identity |
| Layer boundaries and import direction | Holds; no new edge |
| Failure behaviour | Guarantee cannot raise; unknown shapes fall back to a derived sentence |
| Extension points | Table entry per code; one `describe_warning` case per family |
| Intended incompatibilities | F2, listed and tested |
| Whole-architecture check | Consistent with Spec 66 (one engine, many front ends), Spec 50 (facts stay in the Scene), #371 policy (inventory stays the backlog) |
| Open risks carried | F3/F4 successor; derived-sentence quality (F5) |

**Conditions to start code:** the implementation plan names the F1 test change and
the D8 disclosure; the golden diff is reviewed row by row; every new test is
mutation-checked.
