## Scope versus the approved plan

The lead's approval changed the design amendment's schema strategy (no Theme or Layout Profile version bump; extend `theme-v0.11` and `layout-profile-v0.9` in place with additive optional fields) and corrected the swatch-dispatch rule (a closed table keyed on the entry's declared role, not `semantic_binding(role).primitive_kind`, because the committed `milestone` legend role has no `roles.milestone` Theme block). This slice implements exactly that amended design; see the amendment for the reasoning.

**A second correction found during implementation, not anticipated by any prior document:** the phase-1 design and architecture review both stated "no other committed example has a legend slot" besides `halcyon-1/wallboard.yaml`. That was checked only against `examples/halcyon-1/layouts/*.yaml`. `grep -rl "source: legend" examples/*/layouts/*.yaml` shows seven layout profiles declare a `legend` slot: `controller-z/{annotations-review,executive-review-compact,executive-review}.yaml`, `aster-ssd/executive-review.yaml`, `controller-z-ja/executive-review.yaml`, `orion-asic/orion-review.yaml`, and `halcyon-1/wallboard.yaml`. Fixing the actual defect (every legend entry in the corpus was a wrong square) necessarily changes every one of them, not only `02-programme-board`. This is reported here rather than narrowed silently, per the process the lead's brief requires.

## A problem found and corrected before this commit

The first working version defaulted the swatch↔label `gap` (when a Layout Profile does not declare one) to `legend_size * line_height` (the historical per-entry row step). That is **not** what the historical formula's swatch↔label offset actually was: `text_inline = inline + swatch_size * 1.5` decomposes to `width (swatch_size) + gap (swatch_size * 0.5)`, not `width + a full line-height step`. The first version doubled the effective gap, visibly widening every legend's text column and truncating more labels than before (confirmed by rendering both versions). Corrected the fallback to `legacy_swatch_size * 0.5`, which reproduces the historical offset exactly for any entry that keeps the legacy width (verified: `text_inline` now matches the pre-change value bit for bit on `controller-z/annotations` and `halcyon-1/02-programme-board`).

## Architecture review

- **Layout** (`layout/surface_composer.py`) constructs every swatch's geometry: `swatch_geometry(role)` dispatches by a closed table (`milestone` → point; `MARK_GEOMETRY_ROLES` → mark/span; `asOf`/`dependency`/`dependency-critical` → line; anything else → the historical fallback), and `emit_swatch` appends a `MarkPlacement`, `ShapePlacement`, or `RelationPlacement` — the same placement types real marks, bands, and relations already use — never a Scene-side decision.
- **Scene** (`scene/v05_builder.py`) gains one new small loop over `placed_surface.marks` (for the `point` bucket's `Symbol` primitive, reusing the existing `symbol_geometry` function real point marks call) and two one-line additions (`corner_radius` passthrough on the existing legend `Rect` branch; a `legend-swatch:` prefix check in the existing relation loop's `source_ref` derivation). It calculates no geometry.
- **Theme** (`theme-v0.11.schema.yaml`) gains one additive optional per-role property (`swatchInlineSize`); no existing role's resolved meaning changes.
- **Layout Profile** (`layout-profile-v0.9.schema.yaml`) gains three additive optional `slot` properties (`direction`, `gap`, `itemMinInlineSize`), each falling back to today's exact geometry when absent, confirmed by the byte review above (every unmigrated legend slot's arrangement is unchanged; only swatch shape/size, which is Contract 1/2 and always intended to change, differs).
- **Semantic registry** (`model/semantic_registry.py`): `legendEntry.theme_role` is `"legend-swatch"`, separate from `legendLabel`'s `"legend"`. This field was previously read only by the (now-superseded) `primitive_kind`-dispatch idea; it is not consulted for dispatch in the implemented design, only carried as documentation/future contrast-classification surface.
- Two small changes outside the immediate legend block were required by existing shared code that would otherwise silently discard the new placements' `slot_id`: the relation `slot_id` reassignment (`surface_composer.py`, previously routing every relation to `timeline` or `annotations`) and `shape_slot` (already had a `legend-swatch:` case) now both special-case `legend-swatch:`-prefixed placements to the `legend` slot.
