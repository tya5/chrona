## Architecture and release conclusion

One engine behind every front end: the CLI, the tool core and the MCP binding all call the same use cases, the SDK is imported by one module only and is an optional extra (`chrona mcp --list-tools` needs no SDK; [`test_mcp_command.py`](../../../tests/cli/test_mcp_command.py)), and no tool writes, reads a Store, or accepts an integrity override. The extra is `mcp>=2.0,<3`, checked on 2.0.0 to 2.2.0 ([implementation plan](../../planning/active/issue-142-agent-interface-implementation-plan-2026-10-01.md), S4 verification), not the design's `>=2.2`. CI installs the extra in the PR shards and in the three-OS matrix, and an `mcp-floor` job runs the tests against `mcp==2.0.0` ([PR #805](https://github.com/tya5/chrona/pull/805), [`conformance.yml`](../../../.github/workflows/conformance.yml)). Rows 2, 7 and 10 are `narrowed` and rows 11 and 12 are `deferred`, each with an open successor: [#812](https://github.com/tya5/chrona/issues/812) (Store tools: `render_review`, `compare_baseline`, and the pinned-evidence path), [#813](https://github.com/tya5/chrona/issues/813) (mutating tools behind an approval model).

Disclosures:

- **No real agent-host session was run.** The stdio protocol is exercised with the SDK client and raw pipes, not a host application; the implementation plan's transcript requirement is open as [#814](https://github.com/tya5/chrona/issues/814). Later options (HTTP transport, inline project text) are [#815](https://github.com/tya5/chrona/issues/815).
- **Windows and macOS had no MCP evidence before [PR #805](https://github.com/tya5/chrona/pull/805).** The binding tests skip without the extra; the exact-main three-OS run named in the closing comment is the first one that installs it, and its job logs decide whether they ran there.
- **`chrona validate` passes a dependency cycle** that `schedule` and `render` reject ([#780](https://github.com/tya5/chrona/issues/780), open); `validate_project` mirrors it and Spec 66 and the skill say to run `schedule_project` before calling a plan valid. `schedule` key order of `analysis.totalFloat` is hash-seed dependent ([#789](https://github.com/tya5/chrona/issues/789), open); the tool sorts by key.
- **No rendered artifact is inspected here.** No criterion concerns appearance; the tool's SVG and PNG are tested as byte-equal to the command's output.
