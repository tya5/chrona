## Architecture and release conclusion

Schema structure and its loader only. Every slice kept the gate's L1 equal except the listed deltas, and no committed document changed verdict. Rows 1 and 2 are `narrowed` rather than `met` on purpose, and the reasons are below.

Disclosures:

- **Row 1 scope.** The row's literal grep cannot pass while frozen parts and the non-live files keep inline copies. The D8 scope is a design decision, not an owner ruling.
- **The path guard is narrower than the design claimed.** The design said every value the guard rejects was already rejected downstream. That holds for the preset path, the directory and separators, `.` and `..`, but not for a backslash, tab, newline or NUL in the workspace file name: `apply_authoring_command` accepted a workspace whose file carried exactly that name on POSIX. The guard is kept and `my plan.yaml` and `計画.yaml` still work end to end. `.` and `..` hit a `not` rule that the diagnostics reducer does not explain, so the raw message shows.
- **The real Windows escape was found after the design.** The reviewer found on 2026-09-30 that a drive-letter Store address (`C:/…`) escapes the Store root on Windows. The owner decided on 2026-10-01 to tighten it; that work is [#710](https://github.com/tya5/chrona/issues/710), not part of this issue.
- **Decisions not to tighten.** No calendar check and no anchor hardening (`$` kept in existing sites) were decided because tightening accepted values is a #591 question the owner has not ruled on; both are recorded and revisitable.
- **Reader limits.** `corpus_coverage` follows vocabulary parts only, because following every part would add `body.project.store.provider` as uncovered rows to a committed derived doc; that coverage question is open.
- **Open decisions.** The `theme-v0.8` pins (whether to widen the policy's accepted marker shapes), and the `{version, kind, id, body}` envelope across 11 schemas, which was descoped with no successor issue.
- **Derived effect of S4a.** After merge the derived snapshot regenerates one vocabulary-inventory row and one non-gating "uncovered" row in `presentation-coverage.md`, because no committed View uses `end`.

Exact review-bearing-main three-OS CI and newest-Python materializer run must pass before closing #662; record that run in the issue closing comment.
