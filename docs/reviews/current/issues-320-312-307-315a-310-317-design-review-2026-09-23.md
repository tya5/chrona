# Design Review: Reachable, Safe, and Teachable Presentation Surface

## Decision

Proceed with six independently publishable implementation slices.  The design
removes dead policy instead of preserving it, keeps all geometry in Layout, and
makes every newly exposed capability pass through a typed, testable boundary.

## #320 — one truthful public draft-render path

`chrona render` remains an explicit draft-closure command.  It does not gain
implicit View, Theme, Scheme, Layout, or Actual defaults: those defaults would
hide authoring inputs and create a second, undocumented closure policy.

The README will use one tested command containing the five mandatory authored
resources.  A new minimal plan-only example will provide those resources with
`comparison.actual: optional`, no Actual Set, and one declared SVG output.  It
is intentionally a small reproducible regression example, not a premature
curriculum framework.  Its README section states the command's scope and links
to the immutable `render-review` path separately.

Acceptance: the documented command produces an SVG from a clean checkout; a
test invokes precisely the published command; the plan-only View proves an
Actual Set is not an implicit requirement.

## #312 — completed mark bounds must fit their owner row

Layout owns the invariant because it is the first boundary that has row bounds,
track allocation, comparison members, and the Theme mark size together.

`place_mark_tracks` will derive each planned/actual/missing-actual mark's block
extent and reject any extent outside its allocated row track.  A shared track
uses one centred extent.  A stacked member uses its own track extent; its actual
or missing-actual companion is included in the same check.  The error is
`E_LAYOUT_MARK_OVERFLOW` at the resolved `timeline.mark.blockSize` metric.

This is a containment invariant, not a renderer overlap heuristic.  Scene sees
only valid completed tracks, and `SurfacePlacement.assert_valid` gains no
Project or Theme interpretation.

## #307 — delete unreachable conditional style policy

No Render Context binds a style contract, and no schema defines one.  The
projection API therefore drops `style` and `theme`; `_roles` becomes a direct,
total mapping from selected facts (planned/actual/missing/variance/critical) to
semantic roles.  Tests stop constructing the unreachable branch and assert the
public call path cannot accept it.

This deliberately does not resurrect ordered conditional rules.  #314 may
introduce a separately designed, field-driven scale later; it has no implicit
dependency on a deleted private argument.

## #315-A — opacity closure, no literal Scene colour

Opacity is visual policy.  Theme roles declare it as a resolved, finite number
in `[0, 1]`; Scene reads the role's resolved opacity and copies it to its
primitive.  Layout does not choose decorative alpha, and renderers serialize a
completed primitive opacity without recalculating it.

All public themes used by examples and fixtures declare the needed decorative
role opacity explicitly.  SVG emits `opacity`; TikZ emits the target's opacity
form; a target incapable of serializing it rejects the primitive explicitly
rather than silently discarding it.  Tests prove non-default opacity reaches
each supported target and that default primitives preserve their existing
bytes.

`ScenePrimitive.color` is deleted.  It duplicates Theme/Scheme responsibility
and permits a literal-colour bypass.  This slice does not add stroke width,
mixed fill/stroke, or dash semantics.  Those remain open work under #315 and
will be split into a new follow-up before its parent can close.

## #310 — inside labels are a View policy with a completed role

`inside` enters all three View label-side vocabularies: primary side, fallback
ladder, and row presentation intent.  `auto` does not infer `inside`; a View
must request it.  A requested `inside` rung is tried first, then continues
through the declared fallback ladder when the measured text does not fit.

Layout owns fit and selected-rung evidence.  Scene reads that completed evidence
and emits `memberLabelInside` rather than `memberLabel` only for a selected
inside rung.  The semantic registry makes the distinction explicit.

Theme declares `memberLabelInside.fill`.  Theme resolution validates its
contrast against every mark fill role that can host an automatic member label
(planned, actual, snapshot, and scenario), rejecting an unsafe closure before
Layout.  This is intentionally conservative: a single inside-label role may
not silently become unreadable on a comparison mark.  Renderer adapters merely
serialize the resolved role.

## #317 — explicit, maintainable reachability gates

The original report is evidence, not a perpetual baseline: #279 has already
made corner radius reachable.  The implementation adds two scoped checks.

1. A `ScenePrimitive` delivery inventory declares, per non-core field, its
   readers/serializers or an explicit staged exemption with owner and reason.
   The checker parses attribute reads and fails on an undeclared omission.
2. A presentation-vocabulary inventory names the dispatcher and the relevant
   View schema enum.  It checks label sides and axis formats, rather than
   attempting to infer arbitrary strings across the repository.

The inventories are source-controlled contracts.  They prevent a capability
door from disappearing while avoiding false claims about general optional
parameters or unrelated string literals.  A dynamic renderer test complements
the first inventory for non-default opacity and inside labels.

## Whole-architecture review

| Concern | Authoritative boundary | Prohibited shortcut |
| --- | --- | --- |
| Draft invocation | README plus explicit CLI arguments | implicit closure defaults |
| Mark capacity | Layout track allocation | Scene/renderer collision repair |
| Semantic roles | Projection facts and completed Scene evidence | unvalidated style injection |
| Alpha and ink | Theme/Scheme resolution | literal primitive colours |
| Label position | View policy, then Layout measurement | renderer-side fit/contrast choice |
| Reachability | source-controlled quality inventory | heuristic broad lint as policy |

The decisions preserve ADR-0031's completed-placement boundary: View expresses
intent, Theme/Scheme resolve visual policy, Layout completes measurable
geometry, Scene projects it, and renderers serialize it.

## Review disposition

The design is approved for an implementation-plan phase.  Any discovery that
requires a new Theme, View, Project, Layout, Scene, or renderer responsibility
returns to this document before code continues.
