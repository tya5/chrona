# Architecture review — lane label search and attribution (#504)

This review checks the [R2a correction](../../design/issue-504-501-lane-label-search-correction-2026-09-29.md) against the [readable-default design](../../design/issue-504-501-readable-default-design-2026-09-29.md), [prior Layout correction](../../design/issue-504-501-layout-background-correction-2026-09-29.md), Specifications 38/50, R1's context-specific profile and R4's completed scale/2em geometry.

The scope respects ownership: View supplies intent/content; Theme supplies measurable treatment; Layout measures demand, allocates rows, places labels and reports typed suppression; Scene projects completed drawable placements; adapters do not retry or repair. Shared preflight, natural content sizing, final `fill` allocation and lane-only full-band placement are existing Layout seams. The new attribution remains Layout-only, so Scene schema is unaffected.

The current resolver cannot support a factual capacity reason: `resolve_content_block_extent` returns only an integer and silently returns `seed_block` when the final profile solve cannot meet a required source. R2 must retain exact short required-source IDs internally and propagate them to typed Layout evidence. Geometry misses at the final allocated row are `obstruction`, never “cannot grow.” This correction makes no universal claim about hypothetical larger rows: full-band search is exhaustive only over finite events within final row geometry.

Acceptance gates: shared preflight/final content and measurement, completed-scale identity, centered mark obstacles, deterministic complete fixed-row candidates, profile growth/short-source evidence, per-name fact/count consistency, non-lane invariance, and public 02/11/12 materializers with 04/07/15 byte identity. Critical stop gate: if 02 still suppresses after full-band search, pause and design the remaining behavior before claiming #504 complete. This keeps acceptance honest without introducing an unsupported whole-profile/route event solver.
