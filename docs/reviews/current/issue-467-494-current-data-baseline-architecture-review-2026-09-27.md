# Architecture Review — Current-data baseline for #467 cause evidence

**Reviewed:** [current-data baseline amendment](../../design/issue-467-494-current-data-baseline-evidence-amendment-2026-09-27.md), [excess-cause model](../../design/issue-467-494-lane-excess-cause-evidence-amendment-2026-09-27.md), Specs [38](../../specification/38-review-row-composition.md), [46](../../specification/46-completed-scene-paint.md), [50](../../specification/50-constraint-driven-gantt-surface-quality.md), Project 4wd correction, selected lane design and #466 obstacle phase order. **Public base:** `213e71114e34ef42c042976a8e9acadb5a28d033`. **Decision:** accepted for a follow-up implementation-plan amendment.

The dual baseline resolves a real historical-data hazard: the issue's original ten-lane mark-only table is the acceptance reference, while the 4wd current Project is the source for any present-day mark-only comparison. The final Layout plan still closes geometry once; the counterfactual is read-only release evidence and cannot cause a second composition. Source-keyed final rejection traces, not differences between aggregate counts alone, provide attribution. Group-local indexing avoids attributing a later group's first mandatory row to a collision. View and Project retain declarative intent, Theme retains geometry policy, Layout owns both measured traces, and Scene/adapters neither infer nor alter causes.

The risk is an actual current mark-only total other than ten, or a final extra lane caused solely by canvas bounds. Both must be exposed explicitly; the former requires measured mark/chain explanation and the latter returns to design because it is outside the owner's allowed taxonomy. The existing fourteen-lane ceiling, named chain, required text, route gates, public materializer checks and CI remain unchanged.
