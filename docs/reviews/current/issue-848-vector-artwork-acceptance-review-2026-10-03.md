## Architecture and release conclusion

View selects, Theme declares, Layout warps and completes the parts, Scene carries completed `Symbol` parts and decides the omission from the profile, the gate reads the serialized Scene alone, adapters serialize; the View is untouched and the PNG container path is unchanged (an `image` outline is its own artwork; `artwork` is rectangle only).

Disclosures, none of them narrowing a row:

- **A nine-slice stretches the cells it declares.** The scroll's hanger cord sits in the stretched top-centre cell and widens with the note, as any three-slice scroll does; a glyph authored for stretch avoids it. No catalogue entry was edited.
- **One artwork per container, one ink role.** Per-kind artwork, several layers on one container (a clipping with both edges) and a repeated-glyph border (#587) are extension points of the design, not built here; none is part of the acceptance.
- **Typst and TikZ** are as stated in row 6: no adapter route for artwork was shipped.
- **Ink is judged against the label's bounds**, which is conservative at the stroke and exact for fills up to an eight-chord flattening of a quadratic.
- **The evidence slide uses the callout and highlight purposes**, whose text is ground text judged in the Scene gate; the static Theme-resolution check of `annotation-note-text` (dark ink on a light note over a dark canvas) is a limit recorded since #584 and is not touched here.
- **`E_LAYOUT_ARTWORK_SLICE_GEOMETRY`** is a Layout guard that Theme validation makes unreachable from a document.

Exact review-bearing-main three-OS CI and the newest-Python materializer run must pass before closing #848; that run is recorded in the closing comment.
