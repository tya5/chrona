# Architecture Review — Endpoint-Scoped Member-Leader Routing (#554)

**Decision:** approve the [correction](../../design/issue-554-endpoint-scoped-leader-routing-correction-2026-09-29.md) before resuming #554 implementation. The predecessor already forbids whole-host exemption; this closes a pre-existing lane implementation drift exposed by the non-lane extension.

Specs 08/50 keep geometry and collision policy in Layout, with Scene transporting completed paths and SVG painting them. The shared obstacle index remains the single source of mark, text, and accepted-route blockers. The distance metric uses Text bounds; the route attaches to the aggregate decorated label footprint, preventing a line through its own chip/icon. A stroke-aware router-level endpoint-scoped predicate is structurally required because deleting a host obstacle or globally passing its ID through `port_ids` cannot express cap-only contact; filtering only the returned path would also lose a valid longer path. Optional endpoint IDs preserve existing dependency/annotation semantics. Spec 38's lane emission closure remains unchanged; leader source/mark identities are already typed. Tests must prove both direct and visibility-grid searches reject host-body and boundary-length traversal, respect stroke clearance and decoration, and accept legal terminal cap contact, then recheck public lane 26/26 and non-lane association. No new public schema or Theme token is needed.
