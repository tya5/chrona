# Design Correction — Bounded Side-Relative Label Search (#466)

**Predecessor:** [route-priority correction](issue-466-general-placement-route-priority-correction-2026-09-26.md).
**Observed consequence:** route-first HALCYON 03 restores every dependency but suppresses four optional member labels, compared with one in published `main`. The four fixed anchor positions are not an adequate finite candidate set once dependency strokes are obstacles. A spatial probe found legal positions near each suppressed anchor; no new syntax or overlap exemption is needed.

After trying each existing declared side at its canonical anchor position, Layout may search a bounded neighborhood **within that same side** for an optional plot/item/delta label. The fallback never crosses the mark to claim a different side: above/below move tangentially by no more than one measured label width and outward by no more than one measured label height; start/end move tangentially by no more than one measured label height and outward by no more than one measured label width. `inside` is never displaced. A fixed 8-unit lattice, ordered first by Manhattan displacement, then declared side rank, outward displacement and signed tangent displacement, yields at most 512 examined candidates per label. The first in-bounds candidate without a collision in the shared inventory is accepted. Canonical candidates always win; valid old placements do not move. Search exhaustion follows the existing overflow disposition and diagnostic.

The chosen side remains the existing rung; the completed bounds and deterministic attempt count are Layout facts. This is a private finite fallback for current optional plot labels, not the public `nearest-free` candidate grammar, note placement, balloon/tail treatment, or a claim that #466 criteria 2–6 are complete. It does not relax dependency quality, ignore route strokes, or change View/Theme schemas. A displaced name remains visually associated with its host only within the stated measured footprint; if public evidence shows ambiguity, this correction must be revisited before release.
