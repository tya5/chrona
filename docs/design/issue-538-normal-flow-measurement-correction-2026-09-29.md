# Issue #538 — Normal-flow measurement correction

**Corrects:** [Draft-auto design](issue-538-row-following-draft-auto-design-2026-09-29.md) before product code. A raw root `preferred_block` is not a sufficient profile extent: the current grid measurement takes the maximum child, although grid rows consume their sum. Generic `fitWarnings` do not identify whether a shortage can grow.

Layout must expose one renderer-neutral **natural normal-flow block requirement** at the resolved inline extent, derived with the same track rules used by arrangement. A column sums active child requirements, gaps and padding; a row takes the maximum; a grid sums its resolved row-track bases, gaps and padding; a flow counts the lines produced at that inline extent; an overlay includes unanchored children but excludes anchored decoration from the normal-flow minimum. Current grid arrangement derives row-track bases from single-span children only. Multi-span children do not increase those bases; if their allocated span is insufficient, existing visible overflow and typed warnings remain. #538 must preserve this rule rather than invent a span-deficit distribution policy. Source text and slots contribute their measured natural requirements. Fixed/max-capped tracks contribute their declared capacity, not an invented growth promise; content exceeding them remains a typed visible shortage. This measurement is pure Layout data and is shared with its final arrangement, not reimplemented by the use case or Scene.

For Draft-auto, use `max(1, ceil(natural normal-flow requirement))` as the finite sizing floor, then apply the measured table-timeline content-host requirement through the existing #468 resolver. A content-sized candidate is accepted only when the final normal-flow arrangement and all **growable** required hosts satisfy those requirements. Fixed/capped/anchored shortage retains its natural allocation and typed fallback; unrelated overlay overflow is not a reason to enlarge the logical viewport. `rowDistribution: fill` receives only the final surplus and never feeds it back into this measurement. Explicit Draft and immutable finite requests retain the old resolver path byte-for-byte. No generic probe loop, magic iteration limit, or new unstable-layout error is authorized.

This is a Layout measurement/arrangement structural refactor, not a new public resource syntax. Focused tests must include a multi-row grid such as `print-portrait`, a wrapped flow at fixed inline width, an anchored overlay, a multi-span child preserving current overflow, a fixed/capped host, the three-row starter, and immutable finite byte preservation. A new span allocation policy is separate future work, not a prerequisite for this starter sizing fix.
