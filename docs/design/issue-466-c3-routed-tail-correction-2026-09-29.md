# #466 C3 — routed balloon tail correction

**Plan:** [C3 design gate](../planning/active/issue-466-c3-routed-tail-design-plan-2026-09-29.md). **Corrects:** [candidate design](issue-466-candidate-placement-design-2026-09-26.md) and [connector topology](issue-466-annotation-connector-topology-correction-2026-09-26.md). The C4 contrast contract is unchanged.

## Evidence and decision

The current eight-lane HALCYON 02 has free in-plot boxes for its Project notes, but the direct integrated triangle intersects required marks, labels or dependency paths for `tvac-note` and `station-note`. Width probes at 12, 18 and 24em failed with the same obstacle classes, anchor-side rule and 1024-position limit. Larger boxes are not the solution. A strict local orthogonal connection is geometrically feasible for both; the TVAC note narrates actual lateness and therefore anchors to its `actual/body` facet, while station retains `planned/finish`. The actual/body port exits its connected comparison-mark cluster before routing. The planned TVAC finish port lies inside the actual mark and is invalid as exposed egress. These are diagnostic trial facts, not accepted public artifacts.

Keep the existing View `connector: {kind: tail}` and Theme balloon binding. Layout first tests the direct integrated triangular tail for each nearest-free box. If it fails, Layout may form a **routed tail**: a short triangular tip integrated in the balloon outline plus one strict, orthogonal `annotationNoteLeader` relation from the named mark port to that tip. This is one connector with two completed geometric pieces, not an unannounced leader substitution or a rail fallback. A Theme without the balloon binding still errors; a direct tail still emits no relation. The selected decision records `direct-tail` or `routed-tail` topology. No View syntax, Project identity, or Theme token is added.

## Geometry and finite search

For each lattice box, enumerate stable connected-mark egress ports and four exterior box attachments. The short tip lies outside the selected box edge by the existing route clearance; its base remains on that edge, clear of the corners. The route ends at the tip, never traverses the balloon body or its text, and shares the tip exactly with the closed balloon outline. Test the body, both triangular edges, every visible route segment, source egress, and tip together against the one obstacle inventory. The pending box is a temporary obstacle during route search, exempt only at the named attachment; no portion may pass through its interior. Only the named source mark/cluster and terminal tip receive endpoint exemptions. An as-of partition clips the box, egress, route and tip to the anchor side. No bridge, route suppression, hidden obstacle waiver, perimeter escape or fallback-as-fit is permitted.

Use the existing local mark/attachment corridor and quality bounds (at most four bends and the declared detour ratio). The current sparse search's 16-nearest-axis pruning and the 1024-state dense grid miss a real TVAC corridor. Replace that pruning for this connector with finite obstacle-envelope corridor candidates, prioritizing source egress, box-edge ports, and nearby blocking-envelope offsets. Candidate boxes retain their existing `maxPositions` bound; connector states have a separate deterministic 1024 bound, both counted and diagnosable. Rank valid routes by bends, length, source/target port order and coordinates, after preferring a direct tail. Exhaustion is distinct from no fit. The normal next candidate and explicit visible-overflow policy remain unchanged, and an overflow is never accepted as a clear tail.

The box, outline, connector relation and occupied segments commit atomically; rejected trials leave none of them in the index. Layout owns all measurement, search, route and Path commands. Scene carries the completed Balloon and relation with the same annotation provenance; SVG/typeset adapters serialize them without geometric decisions. The existing `annotationNoteLeader` paint role colors the routed segment, while the balloon token and box role color the body/tip. Public Scene/SVG bytes may intentionally change for 02 and dependent materializers only.

## Architecture and acceptance

Project remains the narrative source, View selects the actual/planned semantic facet and ordered candidates, Theme selects balloon and paint, Layout owns one atomic geometry decision, Scene projects, and adapters serialize. This agrees with Specifications 02/06/07/08/33/44/50, the shared-index and connector corrections, #449 visible fallback, and the later C4 note-contrast design. Direct-tail behavior remains first and unchanged when clear; the routed form extends only the `tail` connector's topology, so no compatibility shim is needed. The living Layout specification must replace the prior direct-only wording before code.

Acceptance needs a neutral direct-tail regression, exact strict-routed TVAC/station cases with pending-box penetration checks, overlapping-facet egress, bounded decisions and as-of clipping, no-fit/exhaustion diagnostics, Scene-to-SVG/PNG path parity, all three actual 02 notes clear, and crowded plot-to-rail fallback. Full public materializers and CI remain the #466 release gates.
