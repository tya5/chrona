# Design Correction — Bounded Perimeter Escape for Dense Route Grids (#466)

**Discovery:** With the shared index, controller-z `bringup-risk` has a valid orthogonal route around the obstacle envelope. The standard visibility-grid A* exceeds its unchanged 1024-state limit before reaching it; a diagnostic 32768-state run found a six-point path within the declared 8-bend/2×-detour profile. Raising the limit broadly would make public materialization cost unpredictable. A direct diagonal fallback crosses accepted content.

`route_orthogonal` keeps its current direct-Manhattan fast path and bounded A* search. Only when that search fails by limit or proves no grid route, Layout examines a fixed, finite perimeter-escape family derived from the selected shared-obstacle envelopes: left/right outer x and top/bottom outer y, each offset by the existing grid clearance. A candidate connects start → outer start-y → outer x → outer end-y → end with axis-aligned segments; duplicate vertices are removed. There are at most eight combinations. Every segment is checked against the same selected obstacle classes/regions and named endpoint ports. A candidate outside declared route bounds is rejected. The legal candidate with lowest Manhattan length plus the existing bend penalty wins with a stable coordinate tie-break. The caller still applies the unchanged bend/detour quality policy; the escape is not a free quality exemption. If no legal candidate exists, the existing error/fallback remains.

This is a bounded escape from a dense search grid, not a claim of global shortest-path optimality after the A* cap. The API and resource schemas do not change. All route families may use it through the shared Layout router; Scene/adapter geometry is unchanged in responsibility. Public routes can gain visible orthogonal paths instead of direct fallbacks, requiring artifact review.
