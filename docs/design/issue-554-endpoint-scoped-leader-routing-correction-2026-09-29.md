# Design Correction — Endpoint-Scoped Member-Leader Routing (#554)

Predecessors: [member-leader design](issue-554-member-label-leader-correction-2026-09-29.md) and [non-lane association correction](issue-554-nonlane-member-association-correction-2026-09-29.md). Successors: [architecture review](../reviews/current/issue-554-endpoint-scoped-leader-routing-review-2026-09-29.md) and [implementation amendment](../planning/active/issue-554-endpoint-scoped-leader-routing-implementation-amendment-2026-09-29.md).

The approved leader contract exempts its own label and mark only at path endpoints. Current lane code instead removes the entire own mark obstacle before routing; the router's `port_ids` also exempts named obstacles globally. Either shortcut can accept a path through its host. This existing design/implementation drift must be closed before extending leaders to non-lane names.

The association threshold still uses completed Text bounds. The route's source endpoint instead uses the outer measured candidate footprint (`LabelPlacement.bounds`), which includes its own chip padding and leading/trailing visuals; this avoids drawing through its own decoration. Layout temporarily registers that entire candidate footprint as one source obstacle while retaining the own host mark as the target obstacle. The router receives the two exact endpoint obstacle IDs and validates that each designated point lies on its corresponding obstacle perimeter. The source/target IDs cannot name unrelated obstacles.

Route clearance uses the declared Theme leader stroke width, not a zero-width centerline. A source or target obstacle may overlap only the endpoint cap of that stroke (at most half the stroke width around the designated terminal point); every other part of the painted segment is blocked by the full obstacle footprint. Boundary-length traversal, interior crossing, re-entry, and collisions with unrelated text/marks are forbidden. The same stroke-aware, endpoint-scoped predicate governs the two direct Manhattan candidates and every visibility-grid edge, including their candidate grid offsets; shortest-path ranking never accepts a route that later validation rejects. Generic `port_ids` remain port-only and do not waive label/mark collisions. The temporary aggregate footprint is discarded on candidate failure; accepted label/visual obstacles are registered normally after candidate and route completion.

The endpoint-scoped option is internal to Layout's router and defaults to no exemption, preserving dependency and annotation routing. Leader failure returns to the next already-declared label candidate, then the published suppression/required-failure rule. Lane/non-lane identity and Scene Path schema do not change. Existing lane leader paths may change or become suppressed if they previously traversed their own mark; regenerate public artifacts and review any such difference against the 26/26 lane-name gate. No Scene or adapter route repair is permitted.
