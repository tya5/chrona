# Issue #554 — Member-label leader design correction

**Corrects:** [#554 design](issue-554-lane-followups-design-2026-09-29.md), before slice 554-B product code. The original design omitted the leader's semantic, paint, ports, and route-failure contract.

The new `memberLabelLeader` semantic has Scene purpose/visual role `member-label-leader`; it is a presentation association, never a Project dependency or annotation. Its stable ID is `member-label-leader:<member-label-placement-id>`; source identity is that label's sourceRef and lane/member projection identity. It is a completed Layout `RelationPlacement` with `source_port_id` equal to the label placement ID, `target_port_id` equal to its own host mark placement ID, no arrow marker, and a finite orthogonal path. Scene projects its completed path and lane/member metadata as a Path. Theme may deliberately reuse the existing `dependency` stroke and stroke-width token for this separate semantic, avoiding new resource requirements; Scene purpose and provenance keep the meanings distinct. No adapter search or draw fallback exists.

For a candidate whose completed text box is farther than 2em from its own mark in the nearest-point Euclidean metric, Layout chooses the nearest perimeter pair with deterministic tie order (start, end, top, bottom), then routes an orthogonal path within the owning row band using the shared obstacle index. The label box and own host mark are endpoint exemptions only; other text, marks, and accepted leader routes remain obstacles. Prefer shortest path, then fewer bends, then lexicographic points under the existing finite router. A route with no clear legal path rejects that label candidate and tries the next declared candidate. Only after all candidates fail does existing source-keyed suppression apply. Leaders are inserted in the obstacle inventory before later labels/semantic routes. A name within 2em emits no leader.

The two-em threshold is computed on completed text bounds and mark bounds, not a chip outer box or label placement anchor. Start and end are symmetric; above/below displacement counts. Stable Scene checks join label, host mark and optional leader by lane/member/source identity and verify both endpoints and distance. This correction changes no View schema or lane membership. Existing dependency paint is intentionally shared by Theme, not by semantic identity.
