# Design correction — lane label search and attribution (#504)

This correction narrows R2 of the [implementation plan](../../planning/active/issue-504-501-readable-default-implementation-plan-2026-09-29.md) and supersedes the earlier Layout correction's unspecified full-row search/“cannot grow” proof. See the [architecture review](../reviews/current/issue-504-501-lane-label-search-architecture-review-2026-09-29.md), Specifications 38/50, and [implementation amendment](../../planning/active/issue-504-501-lane-label-search-implementation-amendment-2026-09-29.md).

Layout shares one normalized member-label intent and Theme-measured box between preflight and final placement, including wrapping, font metrics, visual advances and padding. Preflight uses the completed R4 scale and selected mark/subtrack geometry. Inline-feasible end/start intervals and mark-obstacle intervals determine finite stagger demand; centered marks, row padding and required levels contribute to row minima before `fill`. That natural requirement can grow the timeline host when profile constraints permit; a short seed row alone never justifies suppression.

Only lane member names get a lane-specific full-band search, limited to each final allocated row. For each declared side, test the preferred position and finite measured-box contacts with row edges and current axis-aligned obstacle bounds plus clearance. At fixed row geometry, expand obstacles by the label box to form blocked block intervals; preferred position and legal interval endpoints cover the feasible components. Rank by declared side, absolute block displacement, fixed direction and stable identity. The end-side gap remains bounded by R4's 2em rule. Search has no lattice/512 cutoff; non-lane label behavior is unchanged. Do not vary hypothetical row heights or claim an exhaustive cross-height solver.

Record each suppression as a typed Layout fact in `SurfacePlacement` with lane/member, final row extent, remaining row capacity, and reason `capacity` or `obstruction`; validate it against the suppressed `TextPlacement` and aggregate count. “Cannot grow” has the operational meaning that `fill` has no unallocated timeline block available for that row after other row minima and headers. `capacity` additionally requires profile-resolution evidence naming the required timeline source that remains short; `obstruction` means no candidate fits within the actual final row because its inline bounds or current obstacle geometry blocks it. Never label geometric obstruction as capacity exhaustion. The current content resolver returns only an extent and falls back to its seed when constraints prevent growth; extend its internal result to retain exact short-source evidence.
Acceptance is deliberately diagnostic: render 02/11/12 after shared measured preflight, `fill`, and lane full-band search. If context 02 still suppresses any member name, stop R2 and publish a further design correction before claiming #504 complete; do not infer that a remaining miss proves non-growability. No View membership, Scene retry/schema, or adapter behavior changes.
