# Design Amendment — Sparse Elbow Search Before Dense Routing (#466)

**Amends:** [connector topology](issue-466-annotation-connector-topology-correction-2026-09-26.md) and [shared-port fanout](issue-466-shared-port-fanout-amendment-2026-09-26.md). The unpublished controller-z probe found a legal local route with two visible transverse bridges, but dense visibility-grid A* requires more than 4096 expanded states to reach it. Raising the general route cap from 1024 to 8192 makes each annotation trial several seconds and multiplies badly over rail positions.

For an annotation connector, Layout first enumerates a finite **sparse elbow family** derived from the source/attachment coordinates and selected obstacle envelopes. The family includes two-bend `H-V-H`/`V-H-V` and three-bend `V-H-V-H`/`H-V-H-V` paths. Intermediate coordinates are exact source/target coordinates and obstacle envelope boundaries offset by the existing route clearance. Candidates are normalized to remove zero-length/collinear legs, constrained to the local corridor, and ordered by crossing count, Manhattan length, bend count, then normalized coordinate tuple. At most 1024 distinct candidate paths are tested per endpoint/fanout/topology trial. Every leg queries the same typed index: strict paths block all classes; bridged paths block hard classes and then explicitly validate no more than eight transverse route-stroke crossings. A bridge gap is along the *later connector*; clearance from a crossed stroke's endpoint is at least half that stroke's width plus 0.5 layout units, not half the connector's gap length. A junction or coincident endpoint remains prohibited.

If the sparse family finds no acceptable path, the existing 1024-state visibility-grid router remains the bounded general fallback. No global route cap or semantics change. The first accepted path is a deterministic feasible path, not claimed globally shortest; Layout still enforces the unchanged bend/detour profile. The placement decision records sparse candidates tested, dense states if used, topology, crossings and visible fallback. Tests must pin enumeration order and cap, compare sparse/dense collision decisions, and prove the controller-z local route without a slide-perimeter excursion. This is internal Layout search; View, Theme, Scene and adapters do not choose elbows.
