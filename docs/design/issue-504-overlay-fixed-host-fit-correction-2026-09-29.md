# Design correction — fixed overlay host shortage (#504)

The [correction plan](../planning/active/issue-504-overlay-fixed-host-fit-design-plan-2026-09-29.md) found that R2's measured fill-row minimum exceeds the 11 overlay timeline host by 43 layout units. The profile intentionally fixes its review block through Theme token `panel.review.block`; the completed Scene reports `W_LAYOUT_ROW_DENSITY` and keeps natural rows inside the completed canvas. This is the [Spec 33 §13.1](../specification/33-intent-oriented-layout.md) fixed/capped-host fallback, not an allocator failure. The old unit test's unconditional row-within-slot assertion incorrectly disallows it.

Keep the fixed profile, Theme token, measured label minima, row placement and public output unchanged. In the existing 02/11/12 row-ownership test, retain strict slot containment for the growable 02 and 12 profiles. For fixed 11, require a typed row-density shortage tied to the overflowing row, with positive required-minus-available extent equal to the row/host overflow; require all rows and emitted primitives to remain within the completed canvas. Keep separate name-visibility and obstacle/perceptibility checks. A fixed host MUST NOT be reported as grown merely because its rows use visible fallback. No schema, identity, diagnostic, or adapter change follows.

Increasing the shared wallboard Theme token would alter provenance for 02/04/07/10/11 and change 11 composition solely to satisfy an overstrict test. Content-sizing the profile would reverse the accepted #382 fixed overlay decision. Suppressing or clamping rows would contradict the fit-completion rule and #504's measured-label policy. Those alternatives are rejected for this correction.
