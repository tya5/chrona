# Design Correction — Completed lane mark-band anchor in Scene (#467, #494)

**Corrects:** the undefined rigid-move reference in the [rule-based acceptance design](issue-467-494-rule-based-lane-acceptance-correction-2026-09-27.md). **Plan:** [rule-based design plan](../planning/active/issue-467-494-rule-based-lane-acceptance-design-plan-2026-09-27.md). **Public base:** `94d233dc6adfb7e8f361ec2476f9737c906c246f`. An independent whole-architecture audit found that `SceneRow.bounds` includes label rows and therefore is not the mark-band anchor. Inferring one from glyph/icon primitive geometry is also invalid for contain-centered parts.

## Selected contract

For a lane-mode row, Layout returns the completed absolute block coordinate of the **top of its shared mark band** in the same coordinate system as its Scene primitives. Scene projects it as optional `SceneRow.lane_mark_band_block` / serialized `laneMarkBandBlock`. The value is finite and lies within the row's block bounds; it is copied from the one final Layout placement, never recomputed from label-row count, mark primitives, port-host bounds, or row height. A lane row requires this field; automatic/explicit rows omit it and preserve existing bytes. Lane-mode mark/text/icon Scene primitives separately carry the typed `lane_row_id` and `lane_member_id` selected in the predecessor correction. Both values must be present together on every auditable footprint primitive, and `lane_row_id` must refer to an existing lane Scene row. The row's typed group ID determines allowed pair comparisons. Missing or inconsistent provenance fails the checker before reporting acceptance.

The read-only checker translates every source-lane footprint by `target.laneMarkBandBlock − source.laneMarkBandBlock`, leaving inline coordinates unchanged. It tests both move directions and uses completed visible geometry/paint plus the same neutral stroke and clearance predicate. No label-rung search, height solve, reroute or second allocation occurs. `port_host_bounds` is a semantic port container, not an anchor or collision footprint. Group-local primary-mark concurrency still uses Scene footprint intervals and half-open endpoint ordering.

Current public Scene is `chrona/scene/v0.6`, **not v0.5** as incorrectly named in the predecessor design. Add optional lane-only fields to the v0.6 schema/model/serializer; old v0.6 automatic/explicit documents stay valid and byte-identical. The additional fields are completed identity/geometry facts, not a new public row policy. Adapters serialize/ignore them as appropriate but may not infer them. No View/Project/Theme schema changes follow from this correction.

## Required checker evidence

Focused checker tests must cover A→B and B→A separately, same-group-only pairing, a collision-free direction failure, touching half-open intervals, a later group's first lane, multi-part glyph and stroked icon/path visible footprints, required text/delta footprints, raster icon viewport, repeated source instances, missing/inconsistent lane provenance, missing anchor, and a declared chain-only exception that is accepted **only** when a future enforced rule with relation witness exists. The current preference must yield no exception. B2 direct hidden 02 Scene and L3c committed public Scene repeat the same audit; generated SVG/PNG receive a separate visual content review.
