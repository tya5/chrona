# Design Correction — Non-Lane Member Association (#554)

Predecessors: [#554 design](issue-554-lane-followups-design-2026-09-29.md), [leader correction](issue-554-member-label-leader-correction-2026-09-29.md), and product commit `daffc65f`. Successors: [architecture review](../reviews/current/issue-554-nonlane-member-association-correction-review-2026-09-29.md) and [implementation amendment](../planning/active/issue-554-nonlane-member-association-implementation-amendment-2026-09-29.md).

## Gap and rule

Release review of the public HALCYON default found `bus-test` more than 2em left of its own mark without a leader. The published #554 implementation applies the completed association check only to lane labels; the non-lane start-side search is not distance-bounded. This is a semantic gap, not an SVG paint defect. #554 acceptance therefore remains open.

Every emitted plot `memberLabel` with a completed own host mark must be associated with that mark: the nearest-point distance from its completed text bounds to the host mark is at most two font sizes, or Layout emits a completed `memberLabelLeader` relation between their perimeters. Start, end, and staggered positions use the same two-dimensional rule. Leading visuals and chips participate in collision placement, while the measured text bounds determine the association distance. The host is the request's resolved own mark placement, never a nearest unrelated mark.

For non-lane labels, retain the existing declared side order and bounded side-neighborhood candidate search. Do not add full-band search or a new View policy. Capture the completed owning `ReviewRow` band in a dedicated internal `LabelRequest.association_route_bounds` field for plot member names; do not reuse chip-expanded placement bounds or infer row identity from lane metadata. Evaluate each candidate after placement. If farther than 2em, try the existing deterministic orthogonal router within that row band, using the shared obstacle inventory and endpoint-only exemptions. A successful relation uses the existing semantic, ID, source ref, paint token, route ordering, and obstacle registration. A failed route rejects that candidate and tries the next declared candidate. A suppressible request records its existing source-keyed suppression only after all candidates fail. An authored `visible-overflow` member name with an own mark is still retained when its fallback is directly bounded or can be routed; if neither is possible, `E_LAYOUT_LABEL_ASSOCIATION_UNPLACEABLE` fails the render rather than emitting a detached required name. This narrow association rule supersedes the generic visible-overflow fallback, not the fallback for other label families. An applicable actual item without its own mark still raises `E_LAYOUT_LABEL_HOST_UNAVAILABLE`; a planned item without a completed mark keeps its existing host-free behavior and is outside this mark-association invariant. No mark is fabricated.

Lane labels retain their approved full-band search and lane emission inventory. Every plot member label with an own mark carries that mark's exact `host_placement_id` through completed Layout and Scene, including outside/leader placements; this closes the Scene-visible association join rather than guessing from source text or nearest distance. A non-lane leader has no lane row/member metadata and is not added to the lane obstacle/emission inventory. Its Layout relation ports identify the completed label and own host mark; Scene projects that relation as the existing Path purpose with source identity and optional lane metadata, and SVG paints it without routing. This requires no Project, View, Theme, Scene-schema, or resource syntax change. Scene/SVG bytes can change for explicit host references and newly required leaders; public materializers must be regenerated and reviewed.

## Acceptance evidence

The public default HALCYON render must check every emitted member label against its exact Scene `hostPlacementId`, explicitly exercise both start and end, and verify `bus-test` is bounded or has a valid leader in Scene and SVG. Focused Layout tests cover direct <=2em, a routed start-side label, a blocked route falling through the declared candidate ladder, final suppression, and the named required failure including an attached-point visible-overflow case. Existing lane 26/26 and two-theme tests remain unchanged. Batch materializer checks, raw SVG inspection, full CI, and the literal #554 acceptance review follow implementation.
