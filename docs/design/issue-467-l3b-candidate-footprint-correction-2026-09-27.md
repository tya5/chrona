# Design Correction — Atomic Lane Candidate Bundles and Row Translation (#467)

**Plan:** [candidate-footprint design plan](../planning/active/issue-467-l3b-candidate-footprint-design-plan-2026-09-27.md). **Extends:** [L3b preflight/route correction](issue-467-494-l3b-prelayout-route-evidence-correction-2026-09-27.md), [selected lane design](issue-467-collision-aware-lane-rows-design-2026-09-26.md), and [#486 attachment design](issue-486-attached-milestones-design-2026-09-27.md). **Normative home:** [Specification 38 §3.1](../specification/38-review-row-composition.md). **Review:** [architecture review](../reviews/current/issue-467-l3b-candidate-footprint-architecture-review-2026-09-27.md).

## Candidate identity and atomic membership

A lane preflight consumes one **candidate bundle** for each selected primary Review row produced by projection. Its root identity is the row's stable primary/table-subject item identity, not its index or eventual lane. The bundle contains that primary member, any same-object scenario/snapshot/actual comparison member, and #486 selected points already attached to the root by projection. A comparison member is a footprint/provenance facet of the root, not an additional lane-table item or duplicate required name. An attached point keeps its own source/item identity, mark, ports, required title/date/delta label, and lane-table item count; it is pinned to the root's lane before allocation and cannot be independently moved to a different lane. Unattached milestones remain separate candidate bundles and are packed like spans.

The neutral allocator is extended from one-mark/one-label candidates to an atomic tuple of member mark/label footprints. A candidate lane is accepted only if **all** its members' marks and required labels fit the same lane under the declared finite ladder. Within a bundle, comparison and Actual marks for the same semantic object may overlay their host by the named #467 comparison exception, and an attached point may overlay its host span as #486 intends; this exemption does not apply to text or to other bundles. Every required text member gets its own `LanePlacement` and `TextPlacement` identity. A failed attached label candidate tries another rung or another host lane as a unit; it is never silently suppressed or detached. The bundle root is used for first-fit/predecessor preference and stable lane representative identity; the result lists every selected primary item, including attached children, as a distinct member for counts and acceptance.

The View/projection layer does not calculate a lane. Layout reads projection's selected rows and `attached_to` facts, then maps them to closed candidate bundles. The existing `_project_review` fail-closed check remains until L3c; B1 may expose a direct typed Layout seam, but the projection-to-bundle mapper and full public pipeline cannot be considered done from that seam alone.

## Footprint and text closure

Preflight and final composition use the **same** temporal scale from the seed/final invariant and the same Theme mark-role geometry. Each bundle contains stroke/clearance-aware renderer-neutral bounds/segments for every mark that final composition would emit: planned span or point, scenario/snapshot comparison, closed/open Actual (with the selected as-of date), missing-Actual treatment, progress inset, attached point and selected icon-leading visual. The planned interval uses the scheduled `start/end` dates; a point uses its scheduled `at` and resolved point glyph extent. Source identities and ports remain per member even when marks overlap intentionally. A progress fill lies inside its host and does not add an external collision extent; a summary-bar row overlay is not a lane candidate and lane mode does not infer a rollup bar from non-hierarchy grouping. If an intended mark class cannot be closed from available facts before the final block solve, Layout fails before output and the design must be amended.

Required host text is one measured title plus selected `finishDelta` representation. An attached point's required text is its #486 title, short planned date and selected delta; semantic normalization must provide that exact string before preflight rather than later rebuilding it from the final manifest. Text is measured once with the resolved typography and font asset identity; optional icon-leading geometry is included in the same required footprint. The label ladder is tried for every required member in deterministic member order (root first, then attached points by planned `at`, object ID and item ID). A proposed bundle placement is committed only when all its marks and labels fit; no partial member admission or identity reassignment is permitted. A terminal visible-overflow result names the exact member and its source text.

## Final block translation and row sizing

Lane-local coordinates use mark-level top `0`; stagger label row 1, 2 and 3 occupy the consecutive bands above it. The natural content height is `mark_row_height + label_rows_used × label_row_height`. For each completed row, its required block size is `max(row_minimum, table_text_line_block + row_padding, natural_content_height + row_padding)`. The existing content-height solve reserves these values before final placement. Under either `pack` or `fill`, the composer centers the **entire natural content frame** within the row's usable area after half of the total row padding at each edge; its mark level remains at the frame's bottom and is never stretched to consume surplus. In formulas, `frame_top = row_top + row_padding/2 + max(0, (row_height - row_padding - natural_content_height)/2)` and `mark_top = frame_top + label_rows_used × label_row_height`. Every accepted local mark and label geometry is translated by the same `mark_top`. This keeps all used stagger rows inside the completed row and preserves their relative collision result. Table text remains centered independently by its measured line block. #481 group bands span the resulting full rows and their own headers.

The existing `place_mark_tracks` index-stacking behavior is retained for `automatic`/`explicit` and is **not** used to re-stack a lane bundle. Lane mode creates one shared mark level from the accepted plan and verifies each role-specific mark fits that level and row. A later Scene or SVG adjustment is forbidden.

## Alternatives and migration

Rejected: flatten all attached names into the host's one text string (loses per-item identity); place attached points after allocation (can create a hidden overlap or an unmeasured label row); treat comparison overlays as unrelated lane candidates (duplicates names/counts); use `place_mark_tracks`'s member-index stack in lane mode (breaks shared-mark-level design); center the mark alone in a tall row (can push stagger labels beyond the row). The selected atomic bundle and whole-frame translation preserve #486, #480 and #481 while keeping `automatic` bytes unchanged.

No Project, Actual, baseline, View schema, relation quality policy or issue acceptance wording changes. B1's direct seam may publish first, clearly as partial. B2 must prove a neutral attached/comparison bundle, own-label identity, `pack`/`fill` containment, 02 current-data count/chain and all public automatic bytes before the hidden composer path is accepted. Any measured infeasibility or missing member intent returns to design before L3c activation.
