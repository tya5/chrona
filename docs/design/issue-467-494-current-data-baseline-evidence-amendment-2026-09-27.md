## Dual baseline and precise inventory

Keep the historical vector `b_g = (3, 2, 1, 2, 1, 1)` as the literal issue's ten-lane provenance. Separately compute `m_g`, the mark-only vector for the **same current 4wd Project**, the same twenty-six selected root/attached items, group order and deterministic predecessor preference as final allocation. Use completed current Theme/mark/icon/actual/comparison footprints, but omit only required title/delta collision footprints; do not omit a visible mark facet to improve the count. This is an evidence-only counterfactual, never a replacement for the one immutable final plan. Record its exact inputs, code/Project/View commit and vector alongside final vector `f_g` and final total `Σf_g`.

For every group-local final lane whose ordinal exceeds the historical `b_g`, report the lane and its actual final-plan rejected-attempt witnesses. This conservatively covers all lanes contributing to a total above the issue's ten-lane estimate without misclassifying a later group's first lane. Use `m_g` to separate a current-data/mark or chain contribution from additional required-label pressure; report both when they interact. If `Σm_g ≠ 10`, state the discrepancy and its per-group measured mark/chain causes explicitly. If the final count is over ten but a historical-excess lane has no allowed measured witness, the gate fails and returns to design; no global-ordinal relabeling or invented collision is allowed. Final acceptance still requires `Σf_g ≤ 14` and the named chain in one lane.

The final Layout allocation is run once and is the sole authority for composition and rejection trace. The evidence-only mark counterfactual may run separately in a test or release probe with the same frozen inputs, and cannot feed final placement or mutate its source objects. Its predecessor behavior is the existing preference, not a hard rule. An actual `chain-rule` cause requires a separately approved enforced constraint; absent one, only measured mark/required-label collisions may be claimed. This distinction preserves the Layout/Scene/adapter boundary and avoids accepting stale WIP numbers.
