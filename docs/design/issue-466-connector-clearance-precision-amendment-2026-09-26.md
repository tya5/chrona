# Design Amendment — Connector Clearance and Search Accounting (#466)

**Amends:** [connector topology](issue-466-annotation-connector-topology-correction-2026-09-26.md), [fanout](issue-466-shared-port-fanout-amendment-2026-09-26.md), and [sparse search](issue-466-sparse-elbow-route-search-amendment-2026-09-26.md). This records precise O2 implementation choices found during the controller-z/public-materializer gate; it does not define the future public candidate grammar.

The existing visibility-grid clearance is 2 Layout units. A transverse bridge gap is at least 4 units and otherwise equals the resolved width of the crossed stroke plus the resolved annotation connector width plus 4 units. Both widths come from Theme-bound line treatments; Layout registers those widths with the one obstacle inventory. A shared-port fanout step is 6 units: the minimum gap of 4 plus the route clearance of 2. A candidate stub may share the exact initial endpoint with a prior stroke when it leaves transversely **or in the opposite collinear direction**; continuing in the same direction and overlapping the stroke remains forbidden. For a transverse bridge, the crossed-stroke endpoint must be farther than half its stroke width plus 0.5 Layout units. The gap length is measured along the later connector and must not be incorrectly used as clearance along the crossed stroke.

Sparse search tests at most 128 paths per endpoint/topology trial, a stricter bound than the published 1024 maximum. It prioritizes the direct path where orthogonal, corridors adjacent to already accepted route strokes, then endpoint-neighborhood elbow pairs. Strict topology is tried before bridge topology. Bridge choices among the tested sparse family rank by crossing count, Manhattan length, bend count, and normalized coordinates. The existing 1024-state dense graph is a fallback **only after** the finite sparse family has been tried across endpoint/fanout choices; at most two endpoint/fanout choices per box receive a dense trial. A candidate path is deterministic and feasible, not claimed globally shortest. The current Layout `search_count` records box/endpoint-route trials, including dense retries; a later candidate-schema release must specify the public counting unit and candidate ID before claiming #466 acceptance row 5.

No View or Theme schema changes are introduced by O2. Scene receives completed path commands, including every gap; SVG and typeset adapters do not choose clearance or route. Any output migration is recorded in the O2 acceptance review and generated public evidence.
