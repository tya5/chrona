# Design correction — bounded as-of label placement (#501 R4)

Amends the [selected #501/#504 design](issue-504-501-readable-default-design-2026-09-29.md) and its [implementation plan](../planning/active/issue-504-501-readable-default-implementation-plan-2026-09-29.md). The starter reproduction reported for R4 places the as-of label above the plot into the month axis and emits `W_LAYOUT_LABEL_OVERFLOW`; this contradicts the selected requirement that the label remain plot-side and outside every axis lane. The current Layout request in `surface_composer.py` declares `visible-overflow` with an `above` fallback, while `labels.py` can return that fallback without obstacle or bounds acceptance. Spec 50 also describes an axis/timeline seam rung. These rules do not guarantee the required separation.

## Selected behavior

Layout owns as-of label measurement and placement. After axis text, the as-of rule, data marks, and earlier required geometry are completed, Layout first tries the plot's top margin beside the rule, then finite rule-hosted chip positions within the plot. Candidate rectangles must be wholly within the timeline plot slot and avoid axis bands and axis text, every data mark, the as-of rule except at the explicit rule-host attachment, and already accepted required labels/annotations. Later annotation routing must treat the accepted as-of label footprint as an obstacle. The ordered candidates derive from the preferred position and measured-footprint contacts with plot and obstacle boundaries; they do not include an axis-side or unbounded overflow candidate. Candidate generation and obstacle checks use the shared completed Layout geometry and measured label/chip footprint.

If no candidate is legal, Layout leaves the as-of rule visible, completes the label as suppressed, and emits source-keyed `W_LAYOUT_LABEL_SUPPRESSED` evidence for `as-of-label` (with the existing surface-level suppression count semantics where applicable). It does not move the label into an axis lane, overprint data, or enlarge/repair the placement in Scene or an adapter. This is a constrained exception to Spec 50's generic visible-overflow rule for this required marker label. There is no schema change.

## Boundaries and migration

This is a structural Layout change: replace the generic overflow-capable as-of `LabelRequest` path with a typed finite placement decision that consumes the complete obstacle inventory, including axis placements and data marks, and records selected candidate or suppression. The chosen bounds/side and obstacle facts are immutable completed placement evidence. Scene projects the rule and only a successfully placed label; serializers preserve those placements. Scene performs no collision repair, and adapters do not infer policy. Keep ordinary label fallback and other `visible-overflow` contracts unchanged.

The existing #501 first-run gate remains authoritative and must additionally prove on starter and HALCYON that an emitted as-of label lies inside the plot-side region, intersects neither any axis band/text nor data mark, and that no-fit retains the rule while producing a suppressed label with no Scene text primitive. Review generated Scene and public SVG output. Do not claim a visible label when the finite legal region has no room; that case is explicitly represented as suppression.
