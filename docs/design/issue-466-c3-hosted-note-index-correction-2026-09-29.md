# #466 C3 — hosted note-index identity correction

**Predecessor:** [routed-tail design](issue-466-c3-routed-tail-correction-2026-09-29.md). The public batch exposed a case absent from the single-part 02 draft: glyph-gates (#12) emits a planned point mark as multiple Scene Symbol parts, not as the abstract Layout mark ID. A newly selected note's optional number text currently records that abstract ID as `hostPlacementId`; Scene correctly rejects the missing host with `E_PRESENTATION_PRIMITIVE_INVALID`. This is a Layout-to-Scene identity gap, not a paint or adapter failure.

**Rule:** Layout's completed lane-emission mapping is the authority for visible primitive IDs. Before returning placement, resolve a hosted text's abstract mark placement ID to one deterministic emitted host primitive from that mark's typed lane-emission facets (the first painted part, ordered by part index). Retain the abstract mark identity for semantic anchoring and obstacle/route calculations; only the completed Scene host reference uses the emitted identity. Single-part marks keep their existing ID/bytes. A hosted text cannot refer to a non-emitted mark; if no facet exists, Layout raises a typed placement error rather than Scene guessing, silently clearing the host, or fabricating a part. The host primitive must precede the text in paint order and share its slot.

Apply this mapping to all Layout-hosted text that points at a decomposed lane mark, not only note indexes. Scene still projects completed host references and validates them; adapters have no identity fallback. This preserves Project/View annotation semantics, Theme glyph authorship, and the #505 Layout/Scene boundary. No public schema/version change. Test a one-part mark and a two-part glyph note index, exact host identity/order, and 02/11/12 Scene/SVG materialization; inspect the rendered glyph and note number.
