# Design — Integrate Five Independently Tuned Presets (#470)

**Plan:** [integration design plan](../planning/active/issue-470-catalogue-preset-integration-design-plan-2026-09-26.md). **Inputs:** PRs [#471](https://github.com/tya5/chrona/pull/471), [#472](https://github.com/tya5/chrona/pull/472), [#473](https://github.com/tya5/chrona/pull/473), [#474](https://github.com/tya5/chrona/pull/474), [#475](https://github.com/tya5/chrona/pull/475), and [issue #470](https://github.com/tya5/chrona/issues/470). **Scope:** accept, update if needed, and serially merge the five YAML-only tuning PRs; no mechanism change or change to the bare `chrona-default-draft`.

## Intended user behavior

`chrona preset copy <id>` acquires a complete, project-generic View/Theme/Color Scheme/Layout bundle for each of the five catalogue IDs. The copied bundle renders both HALCYON-1 and the three-item `chrona init` starter through the ordinary `--preset` path, without corpus-specific IDs or dates. The preset catalogue points each entry to its own members under `src/chrona/resources/presets/bundles/<id>/`. A library entry may still reuse a genuinely generic Color Scheme resource, but cannot silently borrow another preset's View, Theme or Layout. The bare render default `chrona-default-draft` remains outside #470 (#468 ownership).

For the literal 1600 × 900 acceptance, the numbers name the **requested render viewport**. The completed SVG/canvas may grow in block extent under Specification 50's natural content and visible-overflow policy. This interpretation is required by the PR evidence itself: the 26-item `print-mono` and executive variants visibly exceed 900 px while reporting zero fit warnings. Treating 900 as a clipping or forced-shrink target would contradict the existing Layout contract and the issue's own desired PRs. The acceptance review must report both requested and actual dimensions, not conceal the difference. HALCYON at that request must produce zero `W_LAYOUT_*` and zero `W_SCENE_TEXT_INTERSECTION`; the starter's characterized as-of warning is not silently generalized to HALCYON.

## Source and responsibility boundaries

The preset library stores references to package members, not resolved pixel geometry. View owns project-generic selection, grouping, table, label and axis intent. Theme owns named paint and typography treatments. Layout Profile owns slot allocation; Layout computes geometry under the accepted #466 obstacle closure. Scene/adapters remain projections and serializers. PR-specific research images and READMEs are review evidence, not runtime bundle members. Each PR must change only its own bundle/reference and the shared packaged-resource test assertions; shared `library.yaml` and test edits are reconciled by merging against the latest public `main` in serial order.

The current preset treatment is intentionally limited by published mechanism vocabulary. A YAML-specific workaround may use existing supported values only when it does not create a false semantic fact or mask an error. Every discovered non-YAML gap has a distinct owning issue: #476 missing actual, #477 diagnostic pointer, #478 silent drops, #479 generic-expression limits, #480 table/row metrics, #481 group bands, #482 axis edges, #483 readable defaults, and #466 plot-label/route interaction. #470 does not implement those issues. A later mechanism change may motivate a separate preset update; that does not invalidate the initial YAML-only merge if current acceptance is met.

## Merge and regression contract

One PR per preset is retained as public provenance. Before each merge, refresh target `main`, inspect the PR's current head and changed files, confirm no unrelated overwrite, and verify its existing CI is green. Because the PR checks were run against older bases, an up-to-date merge commit and current-main CI must be inspected before the next PR. If a PR is not fast-forward/cleanly mergeable, update it with a normal follow-up commit or stop and reconcile; do not force-push `main` or overwrite a concurrent update. Merge commits are acceptable; a final combined change without five merged PR records is not.

After all five merges, render from copied packaged presets, not the source bundle path, for both projects. Compare warning inventories, source identities and actual rendered images in one batch. Existing committed corpus public materializers must remain byte-identical because no corpus resource is changed. Update and publish a literal acceptance review; close #470 only when all three rows have direct evidence. #466 C2/C3 resumes on the merged preset base.
