# Design Correction — Lane Preflight and Route-Cause Closure (#467, #494)

**Design plan:** [L3b pre-layout design plan](../planning/active/issue-467-494-l3b-prelayout-route-evidence-design-plan-2026-09-27.md). **Corrects:** the [selected lane design](issue-467-collision-aware-lane-rows-design-2026-09-26.md), [feasibility/route correction](issue-467-494-lane-feasibility-route-correction-2026-09-27.md), and [L3 publication ladder](../planning/active/issue-467-494-l3-lane-completion-publication-amendment-2026-09-27.md). **Normative updates:** [Specification 38](../specification/38-review-row-composition.md) and [Specification 50](../specification/50-constraint-driven-gantt-surface-quality.md). **Review:** [whole-architecture review](../reviews/current/issue-467-494-l3b-prelayout-route-evidence-architecture-review-2026-09-27.md).

## Why a correction is required

The published pipeline measures sources and resolves a content-coherent timeline height before the final Layout manifest and `compose_surface_layout`. A lane's measured mark and required text can use up to three stagger rows. Computing ordinary row extents before the allocator, then selecting lane extents after the height solve, is a real ownership/feasibility cycle. The current route loop also discards each failed port pair's reason, so a generic suppression warning cannot prove #494's measured-cause criterion. Neither gap may be filled by Scene inference or a HALCYON-specific conditional.

The design plan called the preflight “geometry-free.” That wording is too strong: the allocator needs **inline** mark coordinates and finite text widths. The correct invariant is **final-block-coordinate-free**. It uses a finite seed Layout manifest's table/timeline inline bounds and fixed measured inputs; it does not depend on final block positions, final route geometry, or post-routing labels.

## Selected Layout preflight contract

For `rows.mode: lanes`, perform one deterministic preflight after normalizing semantic item/group/label intent, measuring the necessary Theme/font assets, resolving the Layout Profile, and making a normal seed arrangement at the requested finite viewport. The seed arrangement supplies the actual table/timeline inline slots and temporal scale. The preflight closes renderer-neutral mark/comparison/actual/attached-point footprints, measured title and selected delta, group-local membership and ladder choice with the L3a allocator. It returns an immutable `SurfaceLanePlan` containing:

- the exact canonical lane order/identity, representative and member identities, selected label rung and lane-local measured geometry;
- exact natural lane block requirements, group-header requirements and table-summary facts, with no absolute final block coordinate;
- the seed table/timeline inline bounds and the font/Theme/scale identities used to derive the plan, so a mismatched final realization fails rather than silently repacks.

The same plan is consumed by `timeline_content_block_requirement` (alongside #480's table text line block) and by the final surface composer. The composer translates its lane-local placements once into final row positions. It must not re-run allocation or choose a different ladder after the content-height solve. Group bands include the expanded lane rows and their own #481 header. #486 attached points retain their selected primary identity but share the host lane and contribute their actual footprint before allocation. Summary bars, comparison ghosts, actual lines and point glyphs contribute footprint or declared row overlay; none may appear later as an unmeasured obstacle that invalidates membership. If a needed footprint cannot be closed at preflight, fail before output or return to design; do not silently under-reserve.

The seed and final arrangements must have identical lane-driving table/timeline inline bounds and temporal scale. Layout Profiles can couple inline size to block size via aspect-ratio constraints, so this is checked on the actual final manifest. If unequal, lane mode fails deterministically with `E_LAYOUT_LANE_INLINE_UNSTABLE`; it does not silently use mismatched coordinates or loop until an accidental fit. A future iterative profile contract requires a separate design. The existing `automatic`/`explicit` pipeline is left byte-identical and does not create a lane plan.

### Lane table measurement before membership

`rows.laneTable` is a finite group/lane summary, never an item-subject `tableColumns` projection. Its column identities (`Lane`, optionally `Items`) and candidate text set are known before membership: all resolved group titles and all eligible representative item titles bound the label column; `len(selected primary items)` bounds the decimal count width. Layout constructs this conservative measurement envelope using the same #487 measured-column path and Theme font metrics; it is not a second table policy in View or Scene. The final plan then constructs exact per-lane cells (group title on first lane only, or representative title, and exact member count). The source measurement remains the conservative envelope through seed and final solves; this intentional width reservation prevents a lane-count feedback loop. Final cells may be narrower but may not exceed the measured envelope. The timeline/table block requirement uses the plan's **actual** lane count and natural heights, never the original per-item count. The exact cells and plan identities must agree one-to-one.

Detail-profile content that genuinely needs the final manifest remains post-solve. Preflight consumes only the manifest-independent semantic facts it needs; `normalize_v05_surface_content` is not called twice to manufacture a hidden loop. Other source inputs and immutable Context references remain unchanged.

## Phase order and relation labels

The preflight does not route. Final Layout realizes rows, marks, ports, lane table and every required packed title/delta, registers their measured bounds in the single obstacle index, then routes semantic dependencies. A route body and either endpoint egress may not cross a required lane/member label. The only egress host exemption remains the named host-mark corridor, never a text exemption. Relation labels are a different class: their anchor is selected from the **completed** relation path and therefore they are placed after that path, as already implemented. Optional member/annotation labels follow their existing #466 priority. “Required labels before routes” means required lane item names/deltas and other route-independent required text, not route-derived relation labels. No change to the declared route quality limits is authorized.

## Typed route-attempt evidence

Layout records one immutable attempt for every deterministic endpoint port pair, in existing nested candidate order. An attempt has the port sides, outcome `egress-collision | no-route-found | quality-rejected | accepted`, and only applicable measured facts: blocker obstacle IDs for egress; bounded-search failure for no-route; finite actual length/direct length/bends and declared limits for quality rejection or acceptance. Narrow the router's no-path result to a typed result/exception so an unrelated `ValueError` cannot be misreported as a search failure. A quality-rejected attempt must demonstrably exceed bend or detour bounds; an accepted attempt must satisfy them.

An accepted relation has a completed path and no suppression evidence. A suppressed relation has no path, at least one failed attempt, no accepted attempt, and typed `RouteSuppressionEvidence` carrying the ordered attempts and a primary cause. The primary cause is the furthest stage any pair reached: `quality-rejected` if any path failed quality; otherwise `no-route-found` if any pair cleared egress and search failed; otherwise `egress-collision` when every pair stopped at egress. Preserve mixed per-attempt counts and blocker IDs; the primary cause is never used to erase them. A visible-overflow direct fallback is not called an accepted quality route and retains its existing warning.

Layout emits the existing `W_LAYOUT_RELATION_SUPPRESSED:<relation-id>` unchanged plus a stable, lane-only cause diagnostic with relation identity, primary cause, attempt counts and failing quality measurements sufficient for review. The typed evidence remains the source of truth; Scene only projects those completed diagnostics and geometry, and adapters serialize them. Existing non-lane Scene/SVG bytes and suppression diagnostics remain unchanged. Adding a new public Scene field or schema is not required for this slice; if the current diagnostic carrier proves insufficient for the measured evidence, return to design before changing serialization.

## Alternatives, migration and acceptance

Rejected: allocate lanes after the height solve (under-reserves rows); independently recompute lanes during composition (two authorities); blanket label/endpoint exemptions (routes cross required names); loosen bend/detour limits to hide suppressions; infer causes from Scene warnings; and force a generic aspect-ratio profile through the two-stage contract. The selected design is a finite seed-inline plan, one content-height solve, one coordinate realization, and typed route accounting.

This correction changes no View syntax, Project/Actual/baseline facts, route policy, or #467/#494 literal acceptance wording. L3b may publish as a hidden, directly tested Layout path while public `lanes` rendering remains fail-closed; L3c owns resource activation and rendered evidence. Required evidence includes unchanged automatic bytes, 02 lane count/membership/chain and every packed name/delta, zero egress-collision suppressions with measured causes for any remaining suppression, and no required-label crossing on 02/11/12. The separate Editorial/default decision controls the #467 packaged-preset migration and is not inferred here.
