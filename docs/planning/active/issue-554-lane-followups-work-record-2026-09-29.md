## Selected design and whole-architecture review

**Published behavior retained.** A lane table displays the sole member's Project title; for multi-member lanes it displays the titled group, disambiguating repeated group lanes with the founder title, or the founder title alone when ungrouped. Generated/explicit lane keys are identity, never display fallbacks; a missing required human title is diagnosed. The 03 View omits its constant `Items` column. The wallboard uses content-measured table width so human titles do not cross the axis. A successful render has one ordered warning ledger projected to both CLI and Scene with duplicate identities preserved; Scene-only informational facts and detailed `fitWarnings` remain distinct. The same translucent closed-day Theme token paints chart and legend, each passing the 1.15:1 starter gate; #497 truncation is separate. These published decisions for rows 1, 3, and 4 remain in force.

**General rule.** A plot member name with a completed own mark may be emitted only when the nearest-perimeter distance from its completed Text bounds to that exact mark is at most `2 × Text.fontSize`. Layout evaluates each existing declared side in order. In a lane, its `fill` contact search considers the preferred position and contact positions within **one measured stagger step** (`measured label height + declared gap`) above or below it, never a second step or a remote row. Exactly one legal candidate is selected; equal absolute offsets prefer the smaller block coordinate, then stable identity. The default end-side failure proceeds to `start`; authored side/fallback order remains authoritative. Non-lane mode keeps its existing finite side-neighborhood search but applies the same final distance check on both sides. A candidate failing fit, collision, or association is rejected before the next candidate. Suppressible exhaustion records the existing source-keyed suppression fact and aggregate count; a required or visible-overflow name with its own mark fails with `E_LAYOUT_LABEL_ASSOCIATION_UNPLACEABLE` rather than emitting detached text. A missing actual host retains `E_LAYOUT_LABEL_HOST_UNAVAILABLE`; hostless planned names retain their prior behavior. No member-label leader is emitted.

**Identity and layers.** Layout attaches the exact own mark placement ID to every emitted plot member Text, including non-lane and start-side names. Scene validates and projects this `hostPlacementId`; the SVG adapter serializes it without choosing geometry. Lane row/member provenance remains optional outside lanes. View/Theme/Layout profiles retain project-specific label content, side/fallback, font metrics, and row distribution; no project-name branch or new schema knob is introduced. A project may tune its declarations to show more names, but Chrona does not promise a particular corpus count for arbitrary inputs.

**Compatibility and evidence.** In one atomic product/resource slice, remove the #554-specific `memberLabelLeader` semantic, member-leader Scene projection, and `leader-route` values from the versioned Scene v0.6/v0.7 *laneObstacle* enums and validators; both existing `hostPlacementId` schema fields remain. Retiring the short-lived enum without a version bump intentionally makes old member-leader Scenes invalid, so regenerate every affected public Scene/SVG with source changes. Preserve the shared `leader-route` obstacle class used by annotation routing. Compare the entire public batch, report shown/suppressed counts, inspect raw SVG, and update project resources only through existing declarations. The previous 26/26 HALCYON result is characterization evidence, not a general placement invariant. Any reduction is a visible migration to review against #504's growth/obstruction facts, not a hidden success.

**Project tuning probe.** In an isolated read-only release experiment, changing only HALCYON wallboard Theme `size.body` from 15 to 13 made 02/11/12 each show 26/26 member labels, no suppression and no member leader; maximum Text-to-own-mark gap was 19.13px against 26px. Raw SVG contained 26 member-label texts at 13px in each, Scene perceptibility reported zero errors, and the existing viewport/text-over-mark gate passed 58 tests. View side/fallback variants did not solve the original 15px case. The 13px Theme variant is a concrete project-YAML migration candidate, **not** a core acceptance condition or a visual-quality approval: inspect readability against the approved target before committing it. No Project or Actual data is changed.

**Architecture review.** Specs 08, 33, 38, and 50 retain the same ownership seam: View selects intent, Theme supplies measured treatment, Layout completes geometry and a typed outcome, Scene carries exact ownership and diagnostics, adapters serialize. The rule is independent of HALCYON identifiers and does not add a generic route exemption. It narrows #504's full-band `fill` search only for mark-associated member names, while preserving measured row allocation; a final-row association miss is `obstruction`, never fabricated `capacity`. The [owner-approved #554 scope change](https://github.com/tya5/chrona/issues/554#issuecomment-5889528211) expressly permits counted suppression after adjacent/start failure and thus supersedes #504's historical 02 zero-suppression stop gate for this later association policy. This is a user-visible migration, not proof #504's earlier implementation was wrong. Existing unrelated relation and annotation routes, lane membership, title projection, warning parity, weekend paint, and #497 legend behavior remain outside this change. The release review must check all four literal criteria and the project-resource migration separately; resource tuning may improve HALCYON but does not decide the core rule.
