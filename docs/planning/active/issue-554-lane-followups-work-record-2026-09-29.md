- [ ] Every warning printed by the CLI for a render is also in that render's Scene `diagnostics`, and a test asserts that the two sets are equal.
- [ ] The weekend fill and its legend key pass the starter perceptibility gate.

## Selected design and whole-architecture review

**Published behavior retained.** A lane table displays the sole member's Project title; for multi-member lanes it displays the titled group, disambiguating repeated group lanes with the founder title, or the founder title alone when ungrouped. Generated/explicit lane keys are identity, never display fallbacks; a missing required human title is diagnosed. The 03 View omits its constant `Items` column. The wallboard uses content-measured table width so human titles do not cross the axis. A successful render has one ordered warning ledger projected to both CLI and Scene with duplicate identities preserved; Scene-only informational facts and detailed `fitWarnings` remain distinct. The same translucent closed-day Theme token paints chart and legend, each passing the 1.15:1 starter gate; #497 truncation is separate. These published decisions for rows 1, 3, and 4 remain in force.

**General rule.** A plot member name with a completed own mark may be emitted only when the nearest-perimeter distance from its completed Text bounds to that exact mark is at most `2 × Text.fontSize`. Layout evaluates each existing declared side in order. In a lane, its `fill` contact search considers the preferred position and contact positions within **one measured stagger step** (`measured label height + declared gap`) above or below it, never a second step or a remote row. Exactly one legal candidate is selected; equal absolute offsets prefer the smaller block coordinate, then stable identity. The default end-side failure proceeds to `start`; authored side/fallback order remains authoritative. Non-lane mode keeps its existing finite side-neighborhood search but applies the same final distance check on both sides. A candidate failing fit, collision, or association is rejected before the next legal candidate. Suppressible exhaustion records source-keyed suppression and an aggregate count. Declared `visible-overflow` may emit a near-mark candidate after legal exhaustion despite collision or viewport escape, with the existing warning; it never waives the association bound. A required name with no near-mark candidate fails with `E_LAYOUT_LABEL_ASSOCIATION_UNPLACEABLE`. A missing actual host retains `E_LAYOUT_LABEL_HOST_UNAVAILABLE`; hostless planned names retain their prior behavior. No member-label leader is emitted.

**Identity and layers.** Layout attaches the exact own mark placement ID to every emitted plot member Text, including non-lane and start-side names. Scene validates and projects this `hostPlacementId`; the SVG adapter serializes it without choosing geometry. Lane row/member provenance remains optional outside lanes. View/Theme/Layout profiles retain project-specific label content, side/fallback, font metrics, and row distribution; no project-name branch or new schema knob is introduced. A project may tune its declarations to show more names, but Chrona does not promise a particular corpus count for arbitrary inputs.

**Compatibility and evidence.** In one atomic **core** slice, remove the #554-specific `memberLabelLeader` semantic, member-leader Scene projection, and `leader-route` values from the versioned Scene v0.6/v0.7 *laneObstacle* enums and validators; both existing `hostPlacementId` schema fields remain. Retiring the short-lived enum without a version bump intentionally makes old member-leader Scenes invalid, so regenerate affected public Scene/SVG with the core change. Preserve the shared `leader-route` obstacle class used by annotation routing. A separate local resource slice may tune HALCYON through existing YAML, with its own generated evidence and visual review; it is not a core-rule gate. Compare the entire public batch at each changed behavior boundary, report shown/suppressed counts, and inspect raw SVG. The previous 26/26 HALCYON result is characterization evidence, not a general placement invariant. Any reduction is a visible migration to review against #504's growth/obstruction facts, not a hidden success.

**Project tuning probe.** After the bounded core change, isolated HALCYON Theme trials at 13px body text and 24px large spacing each remained materializable but recovered at most one of six suppressed names per 02/11/12 board; the smaller text reduced readability and the spacing variant did not materially improve the crowded composition. Neither resource candidate is approved or published. The earlier 26/26 result belonged to the superseded routed-leader experiment, not this design. Keep the generic rule independent of that corpus count; compare later gallery tuning against the approved visual target under [#575](https://github.com/tya5/chrona/issues/575). No Project or Actual data is changed.

**Architecture review.** Specs 08, 33, 38, and 50 retain the same ownership seam: View selects intent, Theme supplies measured treatment, Layout completes geometry and a typed outcome, Scene carries exact ownership and diagnostics, adapters serialize. The rule is independent of HALCYON identifiers and does not add a generic route exemption. It narrows #504's full-band `fill` search only for mark-associated member names, while preserving measured row allocation; a final-row association miss is `obstruction`, never fabricated `capacity`. The [owner-approved #554 scope change](https://github.com/tya5/chrona/issues/554#issuecomment-5889528211) expressly permits counted suppression after adjacent/start failure and thus supersedes #504's historical 02 zero-suppression stop gate for this later association policy. This is a user-visible migration, not proof #504's earlier implementation was wrong. Existing unrelated relation and annotation routes, lane membership, title projection, warning parity, weekend paint, and #497 legend behavior remain outside this change. The release review must check all four literal criteria and the project-resource migration separately; resource tuning may improve HALCYON but does not decide the core rule.

**Correction evidence and architecture review.** Focused S1 verification found that `attached-milestones` would fail because its required labels intentionally use declared `visible-overflow` over a parent span while staying beside their own gate marks. The rule above resolves this general collision-policy conflict without an example ID, parent-mark exemption, new schema knob, or Project/Actual edit. Against Specs 08/30/38/50, Layout alone chooses and measures the fallback, Scene carries completed bounds, exact host and warning, and SVG serializes; lane `fill` suppression and unrelated routes are unchanged. Publish the corresponding plan amendment before resuming code.
