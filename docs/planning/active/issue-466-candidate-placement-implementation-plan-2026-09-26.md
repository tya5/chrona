# Implementation Plan — Candidate Placement and Plot Balloons (#466)

**Design base:** [candidate contract](../../design/issue-466-candidate-placement-design-2026-09-26.md), [whole-architecture review](../../reviews/current/issue-466-candidate-placement-architecture-review-2026-09-26.md), and living Specifications 06/07/08/33/44, all published at `29fe09d83adf1263965a8a933b17e95e3b3fc444`. **Prerequisite:** [O2 acceptance](../../reviews/current/issue-466-shared-obstacle-prerequisite-acceptance-review-2026-09-26.md). **Boundary:** implement only the approved candidate/source/tail model; do not change semantic dependency policy or #467 lane packing.

## Literal issue acceptance ledger

1. One obstacle set is computed per surface and used by every placement and leader route. A committed test shows a note beside a dependency line no longer covers it.
2. Placement candidates are declared as region, search, obstacles and connector. The existing rung names expand to candidates, and all committed evidence is unchanged by that refactor.
3. A nearest-free search exists. With candidates plot → nearest-free → tail and no rail slot, HALCYON-1 `02-programme-board` places all three notes without covering a mark, a label or a dependency path, and without crossing the as-of line.
4. The same slide with candidates plot → nearest-free first, then rail, falls back to the rail when the plot is made too crowded, with a diagnostic naming the candidate used.
5. Placement is deterministic and bounded. The placement decision records the candidate chosen and the search count.
6. A Theme can draw the tail and balloon outline. A Theme without it renders as today.
7. The specification describes the model once, and no longer as a list of per-rung behaviours; `06-view-model.md` and `44-usable-explicit-rows-and-annotation-rail.md` point at it.

Row 1 is already met by O2 but must remain green. Row 7 has design text but needs the completed model and acceptance audit. #466 is not closeable while any row is not met.

## Structural and test gates

Run focused tests after each edit and `git diff --check`. Run the 21 public materializers once per slice in a batch, not one SVG at a time. C1 requires byte identity; C2/C3 require exact intended Scene/SVG/PNG changes and refreshed derived reports. CI provides full pytest/conformance/wheel-smoke across three OSes and newest-Python public reproduction; no routine duplicate full local pytest. A material push is not accepted until its CI run is inspected. A red run must have every failed check named and either fixed or explicitly shown independent of the slice. Do not close on a Scene-only test when acceptance names visible HALCYON output.

Before each push: fetch `origin/main`, inspect ahead/behind, staged diff, exact target commits and generated output; publish serially without force. After each push verify remote SHA and CI/PR state. Stop on unexpected remote updates or non-fast-forward. If source-reference, region, search, tail or layer contracts prove inconsistent during C1–C3, pause product code; publish a design correction, whole-architecture review and this plan's amendment before resuming. In particular do not weaken plot obstacle classes, skip a Project note, or increase the search bound ad hoc to make the HALCYON fixture pass.
