## Published baseline and finding

Specifications 15, 40, and 50 require immutable references and exact authored Context bytes. Spec 50 §1 explicitly prohibits reserializing the parsed Context and mutating font metadata. On this base, `copy_context_closure` in `src/chrona/usecases/materialize.py` copies declared resources, then mutates font locators in the parsed Context and YAML-serializes it. For package icon catalogs it also mutates the parsed reference's store and revision. Its returned Context digest therefore describes generated bytes instead of the authored Context bytes. The L1 draft's Project-v2/Theme-v1 asset-root correction does not resolve this conflict.

The 15 HALCYON contexts are `01-mission-brief`, `02-programme-board`, `03-launch-campaign`, `04-tvac-slip`, `05-dependency-network`, `06-flight-readiness`, `07-replan-baseline`, `08-gallery-dark`, `09-gallery-mono`, `10-gallery-network-wallboard`, `11-overlay-briefing`, `12-glyph-gates`, `13-gallery-editorial`, `14-gallery-technical-print`, and `15-gallery-image-notes`. All declare package-provided font metric/font locators with content identities. Context 15 also declares the corpus icon catalog; its current reference is local. The current renderer defaults font lookup from Theme revision even though the materializer stages Context font assets under Context/Project revision. The L1 migration proposes pinning the exact current Project digest in all 15 contexts while keeping Theme pins unchanged.

## Dependencies and decisions to settle

- Preserve the authored Context payload byte-for-byte, including its SHA-256, references, locator provider/identity/address fields, and absent optional fields.
- Verify each copied resource/asset against its authored identity before it enters a transient render closure. No host package installation or current-file fallback may repair a missing/mismatched pin.
- Select an execution-only resolver overlay that lets renderer inputs retain authored identities while reading the verified local copies.
- Keep the overlay owned by materialization/use-case plumbing and the resolver contract at the resource boundary; Layout, Scene, and output adapters receive resolved metrics/icon payloads only.
- Define failure diagnostics, overlay key identity, cleanup/lifetime, and package/local behavior for all assets actually consumed by the target.
- Preserve the separate L1 Project correction, all 15 Project pins, Theme references, Actual, frozen baseline, and historical #498 I2 artifacts.

## Proposed independently publishable slices

1. **Design authority:** publish this plan, the selected design correction, whole-architecture review, and Specification 50 clarification before code.
2. **Generic immutable overlay implementation:** materializer stages verified resource/font/icon bytes without rewriting authored Context; a resolver overlay keyed by full authored locator/reference identity serves those bytes to closure/font/icon resolution. Add focused positive, mismatch, missing, and byte-preservation coverage. Publish as an independently reviewable materializer slice.
3. **L1 closure integration:** apply Project 4wd correction and exact digest pins to all 15 contexts; correct `render_review`'s default asset root to Context identity; materialize all affected contexts and update current dependent output evidence. Preserve unchanged Theme, Actual, frozen baseline, and historical captures. Publish only after full public materializer acceptance.
4. **Issue lane/route slices:** continue L2/L3/L4 from the active plan; this correction does not discharge any of them.

## Evidence required

The implementation review must hash authored Context bytes before and after materialization; verify returned Context identity equals that digest; compare parsed font and icon references before/after; verify each copied asset digest and resolver lookup; exercise divergent Project/Context-v2 and Theme-v1 roots; and prove no package/local fallback on missing or stale assets. For L1, enumerate all 15 contexts and compare references, assert Project pins agree with exact Project bytes, keep Theme references unchanged, byte-compare Actual and frozen baseline, inventory all generated files, and inspect Scene plus SVG/other public adapter output. All 15 materializations must complete through the public CLI before L1 publication.
