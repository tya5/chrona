## Structural and migration gates

- The lane table is generated by Layout from `rows.laneTable` intent. Its `Lane`/optional `Items` text envelope is conservative but exact final cells must fit. Never use original 26-item count as the table/timeline block requirement once lane preflight exists. No item-subject table column is admitted in lane mode.
- The seed manifest is a normal finite solve. Only its table/timeline inline bounds and temporal scale enter preflight. The final solve must preserve them exactly; block-dependent inline profiles receive `E_LAYOUT_LANE_INLINE_UNSTABLE` before output. Do not apply this lane-only rule to automatic or explicit output.
- A packed item has one title/delta text placement with its source identity. It is registered before semantic routes. Relation labels remain after their path; annotations follow #466 route priority. Scene does not measure, search or choose a lane.
- Route evidence is typed in Layout. Preserve per-attempt blockers/quality facts and final primary cause; add a stable lane-specific cause diagnostic while retaining the existing suppression warning. Do not change existing non-lane bytes. If Scene's current diagnostic carrier cannot hold sufficient public evidence, pause and amend design/spec/review before changing Scene schema.
- No generated public Scene/SVG/PNG is expected from B1–B3 because lane rendering stays fail-closed and automatic bytes must remain identical. Any generated difference requires explicit cause analysis and review before publication. L3c will own all View/template/preset/Context resource migrations and regenerated evidence together.
- Fetch `origin/main` before every serial push; inspect ahead/behind, staged files, exact commit and generated diff. Verify remote commit and CI after publication. The project virtualenv is the local Python environment; use focused tests locally and CI for the planned full matrix. A red check is analyzed before release review.
