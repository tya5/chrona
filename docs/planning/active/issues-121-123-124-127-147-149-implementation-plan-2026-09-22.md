# Issues 121, 123, 124, 127, 147, and 149 — Implementation Plan

**Design authority:**
`docs/reviews/current/issues-121-123-124-127-147-149-design-review-2026-09-22.md`

## Rules for every slice

Every slice is one independently reviewable PR.  Before merge it runs focused
tests, the full `.venv` pytest suite, schema/conformance and package checks,
import/reachability checks, and all public materializers in one batched run
when the slice can affect output.  It also fetches `origin/main`, verifies the
PR's base/head/diff, waits for successful macOS and Ubuntu CI, then merges
serially.  A design discrepancy pauses the slice: publish a design amendment
and renewed whole-architecture review before changing implementation.

## P1 — #124 inventory foundation and deferred-schema retirement

Add the explicit live-schema manifest, inventory generator, bidirectional
reachability/package test, and generated README index.  Delete deferred/staged
schemas and their isolated conformance inputs, including the M10 DateTime
v0.2 route, only after proving no current product route consumes them.  Retain
the current v0.1 Project temporarily and record it as a migration-pending
exception in the manifest; this exception is removed by P3.

**Acceptance:** exact inventory/README tests, negative unregistered-schema
test, no current consumer of deleted schemas, all inherited conformance green.

## P2 — #147 frozen closure-record conversion

Replace `FrozenDict`/`FrozenList` envelopes and `ResourceContract.body`/
`.document` mapping access with frozen named records.  Construct records after
exact validation, add schema-to-record completeness fixtures, and migrate
closure, render use case, content normalization, theme/layout resolution, and
CLI accessors.  Preserve current behavior and SVG bytes.  Do not add a schema
version or new WBS policy in this slice.

**Acceptance:** mutation-after-decode isolation, validation-before-construction,
schema/record completeness, no production resource consumer typed as a generic
mapping, five public materializers byte-identical, complete suite green.

## P3 — #123 and #124 atomic Date-only Project migration

Add Project v0.3 schema, Core records and validation/scheduling support for
parent forest, rollup schedule, WBS code, planned progress, and closed
dependency relation type.  Migrate every current Project, profile requirement,
snapshot, Context, fixture, and Core path from v0.1 to v0.3 in this same PR.
Delete v0.1, remove its temporary inventory exception, and correct #123's
tracker wording to v0.3.  No DateTime/capacity semantics are introduced.

**Acceptance:** parent/cycle/rollup/code/endpoint diagnostic fixtures,
deterministic normalized hierarchy and schedule tests, no v0.1/v0.2 Project
schema reachable, materializable examples still render, full suite green.

## P4 — #127 WBS projection and presentation

Add one View v0.3 schema/record and migrate all current Views atomically.
Implement hierarchy grouping/explicit-row depth, `wbsCode`/`path` columns,
theme indent token, subtree summary scope, summary-bar registry entry, and
completed Layout placements.  Scene only projects those placements and each
renderer maps the resulting primitive; no layer recomputes tree or geometry.

**Acceptance:** hierarchy selection/order/depth tests; explicit-row validation;
measured table/indent/overflow fixtures; structural Layout-to-Scene test;
SVG semantics/accessibility and byte evidence; complete suite green.

## P5 — #121 materialization and local initialization

Extract the materialization application service from the tool, expose `chrona
materialize`, implement shared explicit store-discovery precedence, and route
all immutable commands through it.  Add safe `chrona init` scaffold templates
from live schemas, remove/replace the tool-only path, and update CLI help and
the guide.  Tests cover precedence, no-store rejection, no overwrite,
materialized identity preservation, and a freshly initialized first render.

**Acceptance:** command/library equivalence, generated project materializes
through the public CLI, old required flags remain accepted only as explicit
overrides (not a second resolver), documentation references live contracts,
complete suite green.

## P6 — #149 typeset target migration

Introduce the next Render Context schema version with `typst`/`tikz` target
and declared typesetter identity, migrate every context/draft builder and
delete v0.7 acceptance.  Add positioned-text Typst and TikZ renderer adapters,
registry entries, target capability rejections, artifact writing, and source
fixtures.  Do not add native reflow or a target-local layout path.

**Acceptance:** source media type/signature/order/identity tests, required
capability rejection, immutable positioned-text fixture equality, declared
toolchain compilation when available, existing SVG/PNG/PDF behavior and public
materializers preserved, complete suite green.

## P7 — #124 final inventory closure and program release review

Regenerate the final exact index after P3, P4, and P6 version replacements,
delete each superseded View/Context/shared schema route, remove migration
exceptions, and verify one live version per kind.  Publish a final architecture
and acceptance review that traces all six issues, generated artifacts, and
remaining deferred capabilities.  Close the six GitHub issues only after this
review and PR state confirm their acceptance conditions.

**Acceptance:** zero inventory exceptions, no duplicate live kind, no stale
guide/schema references, batch public materializer check and generated-SVG
diff, full test suite, two-platform CI, and post-merge issue/commit verification.

## Dependency order

`P1 → P2 → P3 → P4`; `P5` begins after P2 because it consumes the shared
closure/store service; `P6` begins after P2 and after P1's inventory policy;
`P7` follows P3–P6.  P5 and P6 may be prepared concurrently only after their
predecessors merge, but their publication remains serial.  This ordering does
not claim #124 complete until P7.
