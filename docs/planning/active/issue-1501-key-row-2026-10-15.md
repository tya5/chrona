## Grammar

`rows.points: key-row` plus `rows.keyRow: {title}`; `title` is required with `key-row`, a `literalCaption` (1 to 80
characters, no control character). `keyRow` without `key-row` is `E_VIEW_KEY_ROW_UNUSED`; `key-row` without `keyRow`
is `E_VIEW_KEY_ROW_TITLE_REQUIRED`; `key-row` with `rows.mode` other than `automatic` is `E_VIEW_KEY_ROW_MODE`
(explicit rows already name their members; lanes have their own packing, #467). A View whose labels do not show titles
on the plot is `E_REVIEW_POINT_KEY_ROW_LABEL_REQUIRED` (as `group-header`). A View with no point is not an error: no
key row is drawn. All additive in place; the schema `default`s implement nothing.

## Layers

- **View / projection** (`_fold_automatic_points`): moves every point row, sorted by (date, object id), into one
  `ReviewRowProjection` with `key_row=True`, `label` = the declared title, first in the row list. It carries no
  geometry. `FoldedPointProjection` is not used (that is the header mechanism).
- **Content**: the table normalizer gives the key row a title cell in the first column and empty cells elsewhere; the
  cell is not a link target.
- **Layout** owns geometry: `prepare_surface_inline`, after the mark-aware scale is closed, measures each key-row point
  (mark footprints from the same mark composition as the scale, label width in the label role, label gap
  `max(1, fontSize/4)`, chip padding) and packs them with `pack_extent_lanes`. The lane index is written onto the key
  row's items in `SurfaceInlineGeometry.review_rows` only, so the shared projection (identity-bound to the visibility
  index) is untouched. Row height then follows from the existing row requirement closure: `place_mark_tracks` honours an
  item's `key_lane` (lane `n` at `n * pitch`), so `minimum_track_block_extent` yields `lanes * pitch + padding`.
- **Labels**: key-row labels take the start/end ladder of folded points (`end`, `start`; the declared side when
  `start`) inside the row band, never `above`/`below` (that would enter another lane), with `visible-overflow`.
- **Scene / adapters**: unchanged; the row is an ordinary row of ordinary marks and text.

Not a mark-geometry or heading-layout change: mark shapes, bands and the heading slot are untouched; the only
track-planner change is an optional lane index on an item. If review finds otherwise, the slice stops here.

## Failure behaviour

Packing never refuses: a result taller than the viewport grows the surface as any tall row does. A label placed with
overlap is the existing `visible-overflow` warning, not suppression. The unverified edge: a label whose preferred
side leaves the plot falls to the other side, where it may meet a neighbour in its lane; it is still visible.
