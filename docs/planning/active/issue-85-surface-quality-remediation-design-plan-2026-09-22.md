# Issue 85 — Surface Quality Remediation Design Plan

**Status:** Proposed design plan.  **Issue:** #85.  **Baseline:** `5e7c396`.

## Purpose

Issue #85 collects user-visible review-surface defects exposed by the #58
feasibility work.  This plan reopens it from current public evidence rather
than treating its 2026-09-22 report as a timeless implementation prescription.
The result must correct semantics and geometry at their owners, not mask them
with HALCYON-only offsets or regenerated byte baselines.

## Reconfirmed current state

- The row-index signed-day defect is already resolved.  It is not in scope.
- #86 now renders HALCYON's declared summary.  The remaining output-property
  pins are plot text over marks, off-viewport text, point rows shown as
  `in progress`, and empty declared slots on ASTER/controller examples.
- `dateRange` is still ISO-long, table columns have no declared gutter,
  `print-mono` has Theme pattern intent that SVG does not serialize, and every
  calendar-closed day is shaded at narrow day widths.
- Group-header capability exists in Layout, but briefing and print authoring
  do not bind the optional metric; legend/notes availability must be separated
  into a missing-content diagnosis versus an intentionally empty source.

## Design tracks

### Q85-A — Semantic table correctness

Decide the normalized state for an unobserved Actual cell from the selected
item kind, planned dates, and Actual cutoff.  A point and a not-yet-started
span must not claim `in progress`.  Decide the compact, locale-aware
date-range representation and whether it is a new explicit View formatter or
the corrected meaning of existing `dateRange`.

### Q85-B — Layout feasibility and information density

Reconcile plot labels, finish deltas, table gutters, and group headers with
the completed Layout placement contract.  The design must state candidate
order, obstacles, bounds and overflow for every text family; ensure one
finish-delta representation per item; and distinguish a required declared
slot without content from an optional empty source.  It must establish a
generic calendar-closure density policy based on measured day width, never on
an example identifier.

### Q85-C — Paint distinctions on monochrome output

Define how a completed primitive carries declared fill/stroke/pattern form to
the SVG serializer.  The design must make `print-mono` distinguish planned,
actual and missing actual by form, preserve ordinary colour themes, and keep
the renderer an adapter rather than a policy owner.  It must also state the
relation to the future Renderer protocol/output targets in #122.

### Q85-D — Public authoring and evidence

Identify the exact View, Theme, Scheme, Layout and detail-profile changes
needed for all shipped examples.  Core policy and authoring adaptations that
depend on each other must land atomically so every public materializer remains
valid.  Regenerate only changed SVGs through the public materializer.

## Whole-architecture review required

The design must review every track against Specifications 06–09 and 50,
ADR-0031, the Issue #94 completed-content boundary, and the Issue #99 source
architecture.  It must name the single authority for semantic status,
formatting, measurement/allocation, primitive form, paint, and serialization.
Scene may not measure text or select geometry; renderer adapters may not infer
missing policy; Theme may not choose semantic eligibility.

## Non-goals

- No Project schema/version change, scheduler change, output-target seam, or
  manual SVG edit.
- No silent hiding of required information, arbitrary alpha literal, or
  one-off per-slide coordinate adjustment.
- No unrelated #119 validation, #120 draft render, or #122 format work.

## Design-completion evidence

The review must contain an acceptance matrix mapping every current #85 finding
to a semantic, Layout, Theme, renderer, or authoring owner; explicit migration
effects; neutral fixtures plus public-example coverage; and independently
reviewable implementation slices.  A design/implementation plan must be
published and merged before source changes begin.
