# Design Plan: Reachable, Safe, and Teachable Presentation Surface

## Scope

This plan sequences six related open-issue outcomes without mixing their
contracts or shortcuts:

1. #320 — repair the documented render entry point and establish a plan-only
   authored example.
2. #312 — reject marks that cannot fit their allocated row tracks.
3. #307 — remove the unreachable conditional-style branch before a future
   replacement is designed.
4. #315-A — complete the already-declared opacity path and delete the literal
   `ScenePrimitive.color` escape hatch.  Stroke width, simultaneous fill and
   stroke, and dash vocabulary are expressly deferred into separately tracked
   design work.
5. #310 — make the existing `inside` label placement reachable with a semantic
   contrast contract.
6. #317 — add narrowly-scoped structural reachability gates, based on the
   post-remediation codebase rather than the issue's now-stale baseline.

## Design order

### D320 — authored render path

Determine a single supported Quick Start command from the current draft render
use case and bind it to a minimal plan-only closure.  Documentation must invoke
only public commands and committed resources; it may not describe inferred
defaults that do not exist.  The example is a teaching artifact, while the
existing materialized examples remain the regression corpus.

### D312 — Layout capacity invariant

Specify the relationship between a completed row track and mark geometry.  The
Layout boundary, where both values first coexist, rejects a mark that exceeds
its allocated track.  The invariant includes stacked and shared tracks and
applies before Scene.  It does not make Theme infer row geometry or ask a
renderer to repair overlap.

### D307 — remove abandoned policy

Delete `style`/`theme` arguments and the conditional-role branch from
projection unless a validated ingress contract is designed.  No compatibility
adapter is added for a contract that has no closure source.  This leaves role
selection explicit and makes a future field-driven scale (#314) a fresh,
intentional design rather than a revival of stale code.

### D315-A — primitive appearance closure

Trace opacity from its authoritative owner through completed Scene primitives
to every supported renderer.  Decide whether it is Theme-resolved policy or a
semantic placement property; in either case a renderer only serializes the
completed value.  Remove `ScenePrimitive.color`, because literal primitive
colour bypasses the Theme/Scheme boundary.  Define an output property check for
non-default opacity.  Do not add a generic paint vocabulary in this slice.

### D310 — inside-label semantic contract

Open `inside` consistently across every View label-side ingress and fallback
ladder.  Give inside text a distinct semantic role and contrast validation
against its mark fill.  Layout remains responsible for fitting and deterministic
fallback; Scene projects the selected role; renderers do not choose contrast.
An example must exercise both successful inside placement and a short-bar
fallback.

### D317 — structural reachability gates

Re-run the detector ideas against `main` after D307, D315-A, and D310.  Add
only checks with an owned, stable interpretation:

- a typed primitive-field reader/serializer check with an explicit staged
  allowlist and owner/reason;
- a schema-to-dispatch vocabulary check with an explicit allowlist;
- targeted tests that prove each intentionally non-default Scene field reaches
  a supported output.

The checks are review aids and quality gates, not a heuristic prohibition on
legitimate optional API parameters.

## Whole-architecture constraints

| Boundary | Must own | Must not own |
| --- | --- | --- |
| Docs/examples | reproducible public invocation and curriculum scope | hidden defaults or renderer facts |
| View | author intent and label-side policy | coordinates, colour literals, fit calculations |
| Theme/Scheme | visual policy and literal palette resolution | Project traversal or target syntax |
| Projection | selected semantic facts | obsolete style-rule compatibility |
| Layout | capacity, geometry, fitting and completed label placement | renderer fallback |
| Scene | projection of completed geometry and roles | measurements, policy selection, literal colour |
| Renderers | target serialization | semantics or geometric recovery |
| Quality gates | declared reachability/invariants | product-policy inference |

## Publication and acceptance sequence

1. Publish this design plan.
2. Publish one completed design and architecture review covering the six seams.
3. Publish an implementation plan with independently reviewable PRs:
   I320, I312, I307, I315-A, I310, I317, followed by a release review.
4. For each implementation PR: focused tests, full suite, affected public
   materializer checks, generated-output review where applicable, CI, merge.
5. Publish an acceptance review, close only the issues whose complete stated
   scope has been met, and split/defer the non-I315-A paint vocabulary before
   closing #315.

## Exit criteria

The six outcomes are complete only when the public command and plan-only
example work, Layout rejects oversized marks, dead projection policy is gone,
opacity is serialized and literal primitive colour is impossible, `inside`
labels have a checked contrast/fallback path, and structural gates prevent the
same unreachable-capability class from silently returning.
