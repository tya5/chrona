# Issue #1105: relation terminal shape `none` (work record)

Living record for [#1105](https://github.com/tya5/chrona/issues/1105): baseline, literal acceptance, design plan, design, architecture review and implementation plan, published before code. Successor of #1044 (terminal shapes). Edited in place.

## 1. Baseline (read on `92a63645`)

- `layout/relation_terminals.py: marker_geometry` accepts ten shapes and always returns a `MarkerGeometry`. `surface_routes.compose_surface_routes` reads `relationSourceTerminal` and `relationTargetTerminal` unconditionally and uses the geometry for the entry stub length (`head_length`), the terminal straight run of rounded corners (`start_run`/`end_run`), the centred round trim (#1044) and the Scene `marker_start`/`marker_end`. `Scene` and the adapters already treat `marker_start`/`marker_end` as optional: SVG emits `marker-*` only when present, `visual_capabilities` requires `MARKER_GEOMETRY` only when a marker exists, Typst and TikZ reject only a primitive that carries one.
- The shape vocabulary is declared in `schemas/theme-v0.13.schema.yaml` (marker `shape` enum), `conformance/declared-vocabulary-policy-v0.1.yaml` (finite, owner `marker_geometry`) and the generated `docs/diagnostics/vocabulary-inventory.md` (derived; not edited in a PR). The marker value object requires `shape`, `headLength`, `headWidth`, `attachmentOffset`.
- The legend line swatch calls `marker_geometry(marker_token) if marker_token else None`; annotation leaders pass `marker_geometry(...)` as `marker_end` (an optional field).
- Unverified before code: no other consumer reads `.head_length` of a relation terminal (checked by the tests that run the routes with a `none` source and target).

## 2. Literal acceptance (copied)

1. With the source terminal `none`, a relation has no source-terminal primitive, and its first point is the source port.
2. With the target terminal `none`, the same holds at the target.
3. Every other shape gives byte-identical output.
4. Target B declares a `none` source terminal and matches the mock. (Reviewer-owned file; adoption is the reviewer's step, PR #1061.)

## 3. Design plan

Use cases (synthetic Projects; Controller Z is evidence only): U1 source `none`, target arrow; U2 target `none`; U3 both `none`; U4 `none` with a rounded-corner radius and the side-entry stub; U5 legend key of a `none` terminal; U6 an adapter without marker support (Typst, TikZ) draws a relation with `none` terminals.

## 4. Design and architecture review

| Topic | Decision | Why, reverse |
| --- | --- | --- |
| Vocabulary | `none` is added in place to the marker `shape` enum (Theme v0.13), the declared-vocabulary policy list and `marker_geometry`'s accepted set; one expected-delta entry (Spec 56 section 3.2: widening, existing documents unchanged). The generated inventory is regenerated by derived-sync. | Additive; every existing shape is unchanged. |
| Token | The marker object keeps its four required fields; for `none` the three numbers are validated and ignored. | Making them optional for `none` would change an existing `required` assertion (a non-additive schema change). A later version may relax it. |
| Geometry | `marker_geometry` returns `MarkerGeometry \| None`; `none` returns `None`. `None` is exactly the existing "no marker" value of `RelationPlacement` and the Scene primitive, so no Scene or adapter change. | A zero-size `MarkerGeometry` would violate its own invariant and still emit a marker element. |
| Route | With a `None` terminal: no centred trim, no terminal straight run (`start_run`/`end_run` 0), the entry stub length is `0` plus the existing clearance, and the first or last route point is the port, no setback. | The line starts at the endpoint. |
| Legend | A line swatch whose role terminal is `none` is the plain stroke with no terminal (the swatch shows what the relation shows). | Same key as the relation. |
| Adapters | SVG, PNG (resvg of the SVG) and PDF (the SVG through ReportLab) draw the stroke without `marker-*`. Typst and TikZ reject only primitives that carry a marker, so a relation whose terminals are both `none` is drawn there as a plain path (a gain, not a regression); a mixed relation still carries one marker and is rejected as before. | No adapter code change. |
| Contrast and perceptibility | Unchanged: they read paint, not terminals. |  |
| Layers | Layout owns the decision; Scene and adapters are untouched. Files: `relation_terminals.py`, `surface_routes.py` (about six lines at the marker sites; the routing agent's #1108/#1114 work is in the same file, so the PR is rebased on it and kept minimal). |  |
